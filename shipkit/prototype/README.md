# Shipkit 发布面板原型

本机预览：<http://127.0.0.1:8768>。

导航参考 TWGG 管理端：桌面固定 256px 左侧栏，包含菜单搜索、项目管理/系统管理分组、当前项目与服务器信息、选中状态和底部本机控制端信息。手机通过顶部菜单按钮打开覆盖抽屉，支持关闭按钮、遮罩与 Escape；选择页面后关闭菜单。内容区独立滚动。

点击项目名称进入项目详情，再按“选择服务 → 核对计划 → 执行发布 → 查看结果”四步操作。点击外层步骤条切换页面，标题左侧返回父页面。TWGG 默认只选管理后台，可以切换为全量或其他组合，未选服务显示保留版本。运行端统一显示服务器 IP 和名称，名称用于原型展示。

仅外层步骤条参考 Devpilot 的箭头分段样式，内部沿用 Shipkit 的四步发布流程。选择服务区域顶部可以生成计划，也可以直接点击“核对计划”或“执行发布”；进入执行页只准备计划，不自动开始。点击执行内容顶部的“开始发布”才启动六项过程：创建构建机、构建镜像、推送镜像、部署服务、健康检查和释放构建机。

运行中禁用重复开始、返回和其他页面切换。执行结束保留页面，点击步骤条的“查看结果”才进入结果页，也可以点击“再次发布”，按当前版本生成新计划后重新构建、推送和部署。每轮保留独立历史，当前执行页与抽屉展示最新一轮日志。真实脚本支持这种新一轮发布，重复发布不是幂等去重，并会产生构建费用。

点击六项过程中的任一步骤打开右侧日志抽屉，进行中实时更新，未执行显示空态。可以从结果页点击“执行发布”返回日志，页面切换不会自动重跑。

项目详情中的服务名称在新标签页打开服务入口：TWGG 的 backend 打开 API 文档，admin 打开管理端，mobile 打开 H5。网站项目的服务打开本机服务页。这些链接不会发起发布。

在计划页使用“执行场景”组件下拉，可以体验正常完成、健康检查失败后恢复、服务上线但构建机释放失败。下拉支持方向键、Home/End、Enter、Escape 和 Tab。释放失败会保留待处理提示并阻止下次发布，点击“重试释放”解除。执行时可以取消；发布记录支持查看详情和选择服务回滚。连接与配置页提供内存状态检查。

按用户要求，页面标题、按钮、状态、日志与服务入口已移除原型提示。发布、回滚、释放和连接检查仍使用内存中的演示数据，刷新页面重置。原型不会调用 CLI、SSH、云 API 或生产发布接口，不读取或保存凭据；点击 TWGG 服务名称会打开实际网站。界面版本、状态和旧提交号用于展示流程，不代表当前生产状态。

## 启动

在仓库根目录运行：

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory shipkit/prototype
```

保持终端运行，然后打开本机预览链接。直接以文件方式打开不支持 ES modules。

## 验证与结构

模型与导航测试：`node --test shipkit/prototype/model.test.mjs shipkit/prototype/release-navigation.test.mjs`。浏览器验证覆盖选择与计划、标题返回、步骤切换、手动及重复执行、成功与失败恢复、资源释放重试、取消、回滚、示例项目及手机布局，结果见 `qa-evidence.json`。截图保存在 `.impeccable/review/`。

数据在 `data.js`，状态与模拟执行在 `model.js`、`release-simulation.js`，页面在 `views-*.js`，交互控制在 `app.js`。步骤访问门槛在 `release-navigation.js`，可点击步骤条在 `views-release-steps.js`，标题返回在 `page-title.js`。服务器名称与服务入口共用 `project-entries.js`，本机示例入口在 `service-preview.html`。步骤状态与日志过滤共用 `stage-state.js`，日志抽屉在 `ui-log-drawer.js`，下拉在 `ui-select.js`。显示和复制的命令共用 `release-command.js`。

菜单呈现在 `views-navigation.js`，搜索与移动抽屉在 `navigation-shell.js`，布局在 `styles/navigation.css`；日志与错误的显示文案由 `presentation-text.js` 清理，原始模型事件不变。

设计检测器缺少完整解析依赖，使用了降级检查；视觉验收以桌面和手机浏览器实测为准。
