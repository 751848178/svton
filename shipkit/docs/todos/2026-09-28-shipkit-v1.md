# shipkit v1 — 脱离 devpilot 的轻量交付工具链

Routing: `todo-plan`

## 目标

独立的构建/推送/部署工具链，零 devpilot 依赖：

1. 按项目规范（`ship.yaml`）构建 Docker 镜像（构建机 agent，`POST /api/build`）
2. 推送镜像到私有镜像仓库（`POST /api/push`，腾讯/阿里 ACR/TCR 均可，配置驱动）
3. 在运行服务器上部署运行（`POST /api/deploy`，compose + 健康检查 + 自动回滚）
4. 构建机两种形态：动态创建（前期腾讯云 CVM，provider 适配器可扩展）或绑定既有机（static）
5. 控制器 `ship` TS CLI：本机安装，后期可上服务器作为 devpilot 平台能力
6. 控制器与机器之间 **HTTP 开放接口 + 参数触发**，不直接 SSH
7. AI 友好：全命令 `--json`、稳定退出码、agent API 机器可读
8. 运行目标多机可插拔（`runtime.targets`，`--to` 选择），单机只是配置里的特例

## 用户确认记录（2026-09-28）

- 整体方案确认；两处调整：构建机支持"动态创建或绑定既有机"；控制器不得直接 SSH，改 HTTP 接口触发
- 前期腾讯云，后续开发适配器；工具开发完成后用户提供腾讯云权限
- bash 受系统限制 + AI 支持诉求 → TS CLI
- 运行侧单机多 app 起步，架构不得写死单机
