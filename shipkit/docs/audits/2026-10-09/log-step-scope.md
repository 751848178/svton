## 日志作用域

原因：原先日志选择状态和面板由整个ReleaseWorkspace持有，四步切换只替换正文，未卸载日志。

修复：ReleaseExecution拥有日志选择状态与StageLogDrawer；离开执行发布时二者一起卸载，日志请求按既有hook清理。返回执行页会创建新的关闭状态，不需要额外同步effect，也不会自动重开旧阶段日志。

| 验收动作 | 结果 |
| --- | --- |
| 打开构建镜像日志 → 选择服务 | 日志面板0个，页面右侧占位0px，无body滚动锁 |
| 返回执行发布 | 日志保持关闭，点击阶段可重新打开 |
| 打开构建镜像日志 → 核对计划 | 日志面板0个，页面恢复完整宽度；[桌面截图](log-step-scope/plan-log-closed-desktop.png) |
| 打开日志 → 查看结果 | 日志面板0个，页面右侧占位0px |
| 浏览器返回执行页 | 日志保持关闭 |
| 390px打开创建构建机日志 → 查看结果 | 面板0个，页面宽度390px，无滚动锁；[手机截图](log-step-scope/result-log-closed-390.png) |

只读核对当前API清单及既有SSH转发参数，TWGG的实际链路为：

`Shipkit API → 本机127.0.0.1:17410 → SSH → 腾讯云81.70.201.31的127.0.0.1:7410`

这里的127.0.0.1是相对于运行Shipkit控制端的本机而言；它是Agent控制API的隧道入口。服务器身份仍显示在关联项目与目标，不把连接URL当作业务服务入口或服务器公网IP。未输出凭据或修改连接配置。
