# Git 来源与运行配置版本实施验收

日期：2026-10-09。范围是两个已授权模块的本机实现与隔离验收；未发布生产、未推送。原 `shipkit/0.0.1` 仍指向 `0d46cb909aadc24955342a3dafe9c880390a1ca8`。

## 已实现

- Git 项目接入与仓库维护：HTTPS、分支/标签/提交、定义路径、加密 token/用户名、预览提交与保存 CAS。Provider API 读取 commit/spec；generic 使用有界临时目录；完整 checkout 在 Builder。
- 项目运行配置：按运行目标和服务管理公共变量与覆盖、`.env` 导入、草稿 CAS、冻结语义版本、归档。秘密值不通过读取接口返回；明确删除、无需变量和保留已有值分别处理。
- 发布集成：固定源码/定义/连接/凭据/配置快照，发布绑定配置版本并展示逐服务来源。仅配置发布复用摘要镜像，健康检查与历史恢复保留源码和配置归属。
- 运维：显式密钥初始化与缺失密钥保护、新数据库迁移、旧数据兼容、Runtime 能力检查、独立密钥与 Agent 快照恢复说明。

## 复查闭环

- 私有凭据预览先校验仓库地址，防止把已保存 token 发送给不同仓库。
- 保存计划事务重新核对配置版本 scope 与归档状态；在 prepare 等待期间归档的新计划被拒绝，已绑定历史任务保持有效。
- `.env` 异步读取期间锁定整个草稿；冻结必须依赖当前 etag 的成功差异预览。
- 回滚核对计划显示恢复服务的真实来源和历史配置策略，不显示新 ref 或文件策略。
- 环境变量短值及与地址/摘要重叠时，受控协议字段保持原值，自由诊断与未知扩展仍脱敏；真实 Agent 重启恢复通过。
- 冻结任务类型控制对账发现和清理边界，仅配置发布/回滚不会连接 Builder；原 Builder 离线、尚未保存 Job ID 时，Runtime 仍能发现任务并完成对账。

## 使用与后续上线

参见[运维说明](../../repository-runtime-config-operations.md)。正式升级需要备份 DB/log 与原密钥，迁移数据库、配置独立密钥路径，并升级 Builder/Runtime Agent。配置冻结不会修改线上容器，执行发布任务才生效。

首期不含 SSH/OAuth/Webhook、submodule/LFS、构建期秘密注入或运行中进程热更新。临时 ref 适用已登记的服务结构；新增服务先预览并保存仓库设置。生产部署与完整 Git 构建发布仍需选择正式目标单独验收。
