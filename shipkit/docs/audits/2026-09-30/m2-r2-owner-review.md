# M2-R2 第四轮独立复核：回收目录所有权（2026-09-30）

## 结论

**M2-R2 仍开放（P2）。** 新协议确实避免了上一轮“持证活回收者仅因超过 500ms 就失去回收权”的直接路径；239 项回归包含上一轮两个场景并已通过。但回收目录的删除操作没有绑定已确认的所有权，仍存在两个确定性竞争窗口，均实测临界区最大并发为 2、活锁被覆盖。

本轮只复核 M2-R2，没有重开已通过的 R1、R3 和安装脚本结构整顿，没有修改业务源码。

## 窗口 A：死亡判断之后，删除了后来存活的回收者目录

位置：`src/shared/file-lock.ts:107–108`。

1. 原锁持有者与 `.prev/owner` 记录的回收者均已死亡。
2. A 读到死亡的回收者 PID，在递归删除 `.prev` 前暂停。
3. B 清掉同一个残留，创建新的 `.prev`，写入自己的活 owner，通过原锁身份检查，在替换锁前暂停。
4. A 恢复执行旧的 `rm(prev, { recursive: true, force: true })`，删除的是 B 的新目录，而非自己刚才判断为死亡的那一代目录。
5. A 重新取得槽位，通过原锁身份检查，也停在替换前。
6. B 先替换并进入临界区，A 随后替换并进入，最大并发 2。

该场景不依赖 500ms 年龄清理；只调整 owner 缺失分支不能修复它。PID 判活检查本身正确，不代表检查之后对可复用路径的删除仍然安全。

## 窗口 B：owner 发布失败后，清理了竞争者的目录

位置：`src/shared/file-lock.ts:115、121–123`。

1. A 成功 mkdir，尚未执行 owner 的 `writeFile(..., wx)` 时暂停 650ms。
2. B 按年龄清理无 owner 的目录，重新创建槽位，写入自己的 owner，在替换锁前暂停。
3. A 恢复，真实文件系统上的 `wx` 写入返回 EEXIST。当前 catch 没有只退让，而是递归删除 B 的整个 `.prev`。
4. A 重试，重新取得槽位，通过原锁身份检查，在替换前暂停。
5. B 先进入、A 后进入，同样最大并发 2。

因此“wx 失败即可安全放弃”的说明与真实控制流不符：失败后的清理有副作用，而且作用于别人已取得的路径。`dropPrev` 也只按固定路径删除 owner，未校验代次；协议修复应一并明确所有清理操作的归属，但本报告不将未单独复现的分支另列为新问题。

方法：真实文件系统，真实退出子进程 PID 并确认 ESRCH；仅在 rm/writeFile/rename 的真实调用前暂停以控制交错，不伪造返回结果、错误或 PID 存活判断。A/B 为同一进程的并发调用，通过 AsyncLocalStorage 标记；这是协议级确定性交错验证，不冒称独立子进程端到端失败。实测的是互斥破坏、活 owner 被误删和活锁被覆盖，未声称观察到生产凭据损坏。

## 下一轮验收要求

本轮仍是原 M2-R2，同一问题的两个失败入口，不新增平台化范围。

1. 将“回收权获取、owner 发布、残留回收、正常释放、失败清理”作为完整协议处理；每一次清理都必须保证不会触碰后来取得的所有权。
2. 不接受仅在 rm 前增加一次 read/check、只修 catch、只修改时间阈值或删除失败断言。路径在检查与操作之间仍可被复用，必须给出覆盖完整交错的排他依据。
3. 建议优先评估目标平台可用的成熟锁原语，明确锁随崩溃释放、同一进程并发、独立进程并发以及安装包兼容性；若继续自行实现，应给出可验证的所有权代次和恢复规则。
4. 两个本轮失败场景转为持久回归；保留上一轮两个场景、活持有者保护、旧释放者保护、多回收者、崩溃恢复、不可读锁与包内并发。修复后验证正常串行完成，不能以所有调用均失败代替互斥正确。
5. 实施方通过后仍标注“待独立复核”，不要覆盖原审计证据。

真实环境验收状态不变：干净 Debian/systemd、公网可信 TLS、真实远端 registry 推拉、干净服务器到首个应用发布，均保持独立待验收。
