## 4. 真实环境下发现并修复的缺陷（本次验证最有价值的产出）

### 4.1 腾讯 SDK 新版签名构造吞掉凭证（曾误判两把密钥无效）
新版 SDK（4.1.220）客户端构造签名改为 `new Client({ credential, region })`。按旧签名传参时，SDK 把凭证对象当配置解构，`credential` 字段缺失即回填 `{secretId: null}` —— 发出的签名头是字面量 `Credential=null/...`，服务端报 `SecretIdNotFound`。用手写裸 TC3 签名请求 + 猴子补丁抓包定位。
**修复**: `src/providers/tencent.ts` 按新签名构造；两把历史密钥实测均有效。

### 4.2 API 创建的安全组默认**无出站放行**
控制台建的安全组自带“出站全放行”模板，API `CreateSecurityGroup` 建的是**空规则**→ 一切出站被拒。它伪装成了各种“网络超时”：runtime 连公网镜像源失败、builder 连不上 runtime 内网 7411。
**修复**: E2E 脚本补 egress allow；已在配置示例与本文档标注（用已有安全组时需自查出站规则）。

### 4.3 镜像源/Node 源适配器（用户要求的“适配器”落地）
腾讯子网 DNS 对部分公网域名只回 AAAA（无 IPv6 路由），npmmirror/NodeSource 全部“超时”。
**修复**: `bootstrap/install.sh` 内置适配链（可被 `NODE_MIRROR` env 覆盖）：**腾讯内网源 → npmmirror → NodeSource**，公网 curl 全部强制 `-4`；docker 源同样“内网 mirror → get.docker.com”双路。本次构建机 node 20 即由内网源 30 秒装好。

### 4.4 安装脚本哨兵自毁
渲染器 `replaceAll('__AGENT_TOKEN__', token)` 把“未渲染检查”里的哨兵字符串也替换了，导致**已正确渲染**的安装包报“未渲染”。
**修复**: 源码哨兵改为字符串拼接写法（`"__AGENT_TOKEN""__"`），替换不会命中、运行时拼回原串。

### 4.5 资源等待上限过短
该账号 CVM 分配公网 IP 需 8~15 分钟，原 5 分钟超时导致“创建成功却报超时”的孤儿实例。
**修复**: provider 等待上限放宽至 15/20 分钟。

### 4.6 动态构建机缺调试通道（新增能力）
构建机由平台随机密码创建，出问题时无法登录排查。
**修复**: `TencentCvmConfig.loginPassword` 可选项 → `RunInstances.LoginSettings`。本次靠它登录排查了 4.2/4.4。

## 5. 明早即可使用的脚本（当前仓库状态）

```bash
pnpm --filter shipkit build          # 编译（已验证 28/28 单测绿）
pnpm --filter shipkit test

# 两台机器初始化（各执行一次）:
node shipkit/dist/cli/main.js serve-bundle --host <本机公网IP>
#   → 打印一键安装命令, 在构建机/运行服务器上以 root 执行

# 日常（控制器本机）:
cd <项目目录>                          # 含 ship.yaml
ship build                            # 动态建构建机 → build → push → 释放
ship deploy                           # 部署到 runtime（含健康检查/自动回滚）
ship rollback <app>                   # 一键回滚
ship status                           # 多机版本状态
```

配置模板 `ship.config.example.yaml` 已补全新字段（`installUrl`/`preInstallScript`/`loginPassword`）。

## 6. 遗留事项与建议

1. **真实 ACR/TCR 推送**未验证（本次用自建 registry:2 等价模拟）——拿到仓库凭证后只需改 `ship.config.yaml` 的 `registry.url`，链路一致
2. 本机 VPN 拦 22 端口（fake-IP 路由），SSH 操作走了“临时放行 + ubuntu 用户”路径；生产上 builder 全自动、无此依赖
3. 后续优化：builder 预制镜像（免装 docker/node，开机即用）、buildx registry 缓存、`serve-bundle` 公网可达性（当前需控制器有公网入站或像本次一样自托管引导源）
4. 凭证安全提醒：对话中出现过的 API 密钥与子账号密码/MFA 密钥建议轮换（MFA 密钥本机存于 `/tmp/e2e/mfa-secret.txt`，600 权限）
