# Devpilot Google Stitch 屏幕目录

## 1. 使用方式

本目录把 PRD 拆成可在 Stitch 画布中逐批生成、逐屏验收的 Frame。它不是新增功能清单；字段、状态和动作均来自当前 Devpilot 代码、API、既有 V2 设计或已明确标为目标态的能力。

- 桌面基准：`1440 × 1024`，固定 64px 顶栏，左侧导航 236px，内容区自适应。
- 移动基准：`390 × 844`，顶栏保留品牌、团队切换和菜单入口；导航进入抽屉。
- 命名规则：`[分组]-[序号] / 中文名称 / 状态`，例如 `REL-04 / 发布前检查 / blocked`。
- 能力标签：`LIVE` 当前页面可达；`API` 后端能力已存在；`DESIGN` 已有获批 V2 视觉；`BACKEND` 后端有能力但需要补 UI；`DEFER` 本轮明确不设计为可用能力。
- 每个 Frame 必须包含：页面身份、作用对象、当前状态、问题或下一步、唯一主动作、必要的审计/技术证据。

## 10. 必须生成的移动端 Frame

以下移动端状态不可只靠桌面自适应说明代替，必须在 Stitch 中单独出图：

1. `SHELL-06` 移动导航抽屉。
2. `PROJ-01-M` 项目目录卡片化/关键列折叠。
3. `PROJ-04-M` 仓库接入表单。
4. `REL-01-M` 发布单列表。
5. `REL-04-M` 发布阻塞与修复动作。
6. `REL-09-M` 测试部署运行中。
7. `REL-13-M` 等待审批。
8. `CFG-01-M` 环境版本。
9. `CFG-06-M` 部署目标。
10. `DOM-01-M` 域名与入口。
11. `DEP-01-M` 部署记录。

## 11. 跨屏验收

- 项目名称、环境、版本、发布单、Manifest、部署运行和审批 ID 在跨屏流转时必须保持一致。
- `blocked`、`failed`、`warning`、`manual`、`unavailable` 不得只用颜色区分，必须有图标、文字和可访问名称。
- 不允许把列表主动作放入无上下文的大卡片；主动作靠近页面标题，修复动作靠近问题对象。
- 破坏性动作使用确认对话框，明确对象、后果和不可逆范围；普通查看/关闭不使用危险样式。
- 桌面表格在移动端必须保留对象、状态、问题和下一动作；可折叠次要技术字段，但不可隐藏阻塞原因。
