# Devpilot 后台框架 PRD

## 1. 产品定义

Devpilot 是面向团队的软件交付控制台。后台壳层的任务不是展示所有后端对象，而是让用户在同一团队作用域内完成项目纳管、资源准备、发布执行、运行观测和治理审计。

### 1.1 目标

- 用稳定的全局框架承载现有全部后台模块；
- 让用户先看到待处理事项，再查看状态和进入业务模块；
- 明确团队、角色、项目和环境作用域；
- 在桌面和移动端保持一致的导航、身份和错误处理；
- 为项目模块提供可复用的页面宽度、标题、面包屑、表格、弹层和反馈规范。

### 1.2 非目标

- 不在全局壳层复制项目内的发布、配置或证据详情；
- 不新增当前没有业务支撑的聊天、AI 助手或装饰性实时数据；
- 不把管理员、普通成员和审批者的入口混为一体；
- 不在导航中恢复已被现有信息架构降级的重复模块入口。

## 2. 用户与权限

| 角色 | 核心任务 | 可见范围 |
| --- | --- | --- |
| 系统管理员 | 管理资源类型、资源池、团队与平台配置 | 全部模块，包括 `/admin/*` |
| 团队管理员/负责人 | 纳管项目、配置环境、管理资源和治理策略 | 当前团队内业务与治理模块 |
| 开发/运维成员 | 创建发布、查看运行、修复配置、观察日志监控 | 权限策略允许的项目和环境 |
| 审批者 | 审核高风险操作和生产发布 | 审批队列、相关项目证据和审计 |
| 只读观察者 | 查看项目状态、运行证据和审计 | 只读页面，隐藏或禁用写操作并说明原因 |

权限真相由服务端决定；侧栏隐藏仅是体验门控，不能替代 API 授权。

## 3. 全局信息架构

以下导航来自当前 `navigation-items.ts`。Stitch 设计必须保留分组关系，但可以在视觉上收紧组间距。

| 分区 | 入口 | 主要任务 | 状态 |
| --- | --- | --- | --- |
| 仪表盘 | 仪表盘 | 待办、全局指标、最近部署、资源申请、快捷入口 | `LIVE` |
| 项目 | 我的项目、创建项目、应用服务 | 项目纳管、交付工作台、应用/服务视图 | `LIVE` |
| 基础设施 | 服务器、站点、CDN 配置管理 | 计算节点、入口代理、CDN 台账 | `LIVE` |
| 资源 | 申请资源、我的资源实例、资源操作、资源连接（高级）、密码中心 | 按 1→5 的资源旅程申请、绑定、操作和凭证管理 | `LIVE` |
| 运维 | 监控告警、日志中心、备份 | 日常观测、日志查询、备份与恢复 | `LIVE` |
| 治理 | 执行策略、访问策略、操作审批、执行治理、审计事件 | 定义规则、准入、执行队列和事后追溯 | `LIVE` |
| 配置 | 配置预设、Git | 通用模板和仓库连接配置 | `LIVE` |
| 团队 | 团队管理 | 团队与成员管理 | `LIVE` |
| 管理 | 资源池、资源类型 | 平台级资源目录 | `LIVE`，仅 admin |
| 帮助 | 平台文档 | 使用说明和支持入口 | `LIVE` |

`proxy-configs`、旧 `domain` 生成器和旧 `cdn` 生成器不作为主导航。真实管理入口是站点和 CDN 配置台账；旧能力只可作为导出或兼容说明存在。

## 4. 桌面壳层

### 4.1 顶栏

- 高度：64px，白底，底部 1px 分隔线；
- 左侧：Devpilot cube mark + 产品名；
- 产品名后：团队切换器，显示团队首字母块、团队名和下拉箭头；
- 中右：全局搜索；当前最低能力是菜单和入口搜索，结果按分组展示；
- 右侧：帮助入口、语言切换、用户菜单；
- 通知铃铛仅在存在真实待审批、失败运行或 firing alert 聚合时显示红点。若无聚合读模型，隐藏红点，不使用静态假数据；
- 用户菜单包含姓名/邮箱、角色、个人信息入口和退出登录。

### 4.2 团队切换器

`LIVE`：

- 拉取当前用户团队；
- 当前团队显示勾选；
- 团队项可显示成员数；
- 选择后刷新团队作用域数据；
- 菜单底部提供“创建团队”和“管理团队”；
- 无团队时展示创建入口；
- Escape 关闭并把焦点还给触发器，点击外部收起。

### 4.3 侧栏

- 宽度：236–256px；固定在左侧，内容独立滚动；
- 顶部提供菜单搜索；若顶栏已承载全局搜索，侧栏输入可作为相同搜索的快捷聚焦入口；
- 组标题使用 12px 次级文字；入口高度不小于 40px；
- 资源旅程入口展示弱化序号 1–5；
- 当前入口用浅蓝背景、蓝色左边指示和较深文字，不使用大面积实心蓝；
- admin 分区仅 admin 可见；
- 底部固定用户卡，显示首字母、姓名和邮箱；
- 搜索无结果时在侧栏内显示轻量空态，不改变主内容。

### 4.4 主内容区

- 桌面内边距：24–32px；最大内容宽度由业务页面决定，表格页允许铺满；
- 二级及以上路由显示面包屑；项目 ID 应被项目名替换，发布单 ID 应被版本名/版本号替换；
- 页面标题区包含标题、简短说明和最多一个实心主操作；
- 局部错误不能覆盖仍可用的数据；部分加载失败用顶部错误条和重试；
- 页内表格、步骤、详情和抽屉使用同一状态词与颜色。

## 5. 移动壳层

- 小于 `md` 时隐藏桌面侧栏；
- 顶栏分两行：第一行品牌、团队、语言和用户；第二行是“菜单”触发器；
- 展开后显示完整导航，按两列入口布局并限制最大高度；
- 选择入口后自动关闭；
- 任何触控目标不小于 44×44px；
- 长表格优先转为“关键字段 + 行详情抽屉”，不要把 900px 表格硬压进 390px；
- 项目配置左侧栏折叠为带标签的选择器，检查面板改抽屉或行内区域。

## 6. 仪表盘

### 6.1 信息顺序

1. 待办行动：待审批、24 小时失败部署、触发中告警；
2. 全局指标：项目数、运行中部署、待处理资源申请、触发中告警；
3. 最近部署和我的资源申请；
4. 快捷操作。

### 6.2 状态

- 首次加载：主内容 skeleton 或 loading；
- 所有源失败：整页错误条 + 重试；
- 部分源失败：显示失败分区数量，其余数据保持可用；
- 无待办：简短“暂无待处理事项”，不使用庆祝型大卡；
- 每个待办直接进入真实审批、部署、告警或资源对象。

## 7. 全局搜索与行动中心

### 7.1 搜索

- `LIVE`：导航名称和路由本地过滤；
- `DESIGN`：可扩展为项目、发布单、服务器、资源实例的统一命令面板；
- `BACKEND`：跨域搜索需要统一搜索接口和权限过滤；没有该接口前，Stitch 原型只演示菜单搜索，不展示虚构业务结果；
- 快捷键可展示 `⌘K`，但只有在原型中真实打开命令面板时才保留。

### 7.2 通知/行动中心

- `DESIGN`：聚合操作审批、失败部署和 firing alert；
- `BACKEND`：需要返回数量、严重级别、对象、发生时间和目标链接的统一读模型；
- 未实现聚合前可以省略铃铛，不能用静态红点暗示存在未读数据。

## 8. 通用组件合同

### 8.1 状态

- 成功/在线：绿色文字或浅绿标签；
- 运行中/当前：蓝色；
- 待配置/警告：橙色；
- 阻断/失败/危险：红色；
- 未开始/不可用：灰色；
- 发布步骤的“完成”使用浅蓝节点和连线，不与业务成功态的绿色混淆；
- 所有状态同时有文字或图标，不能只依赖颜色。

### 8.2 表格

- 行高 56–64px；
- 表头 12px，正文 13–14px；
- ID、版本、对象名在可进入详情时使用文字链接；
- 独立“操作”列宽度稳定；
- 1–3 个动作全部直出；超过 3 个时直出最高频三项，其余放省略菜单；
- 省略菜单支持 hover、focus、click 和 Escape；
- 行选择只改变详情，不替代明确动作。

### 8.3 问题条

格式固定为：`对象 + 问题 + 影响。具体动作 →`。

- 位于页面身份或对应对象之后；
- 一行问题不升级成 Hero 或大卡片；
- 修复入口在问题文案末尾；
- 同一问题不在顶部、卡片和侧栏重复三次。

### 8.4 弹窗与抽屉

- 创建/编辑/确认使用 Modal；
- 技术证据、日志、历史详情使用右侧 Drawer；
- 一个弹层只允许一个主滚动区域；
- 高风险操作显示对象、影响、不可变输入摘要和确认动作；
- 关闭后焦点返回触发器；
- 错误保留用户输入，并在操作区附近解释。

### 8.5 反馈

- 保存、创建、复制、审批等成功使用轻量 toast；
- 失败必须在当前上下文显示原因，可重试时给出重试；
- 禁用主操作下方常驻显示禁用原因，不能只依赖 `title`；
- 404、无权限、无团队、空列表、筛选无结果使用不同文案和动作。

## 9. 国际化与文案

- 支持中文/英文切换；
- 中文为 Stitch 默认画板语言；
- 用户文案优先业务词：项目、版本、发布、预发部署、生产审批、部署目标；
- Manifest、digest、BuildRun、DeploymentRun、input hash 等只在技术证据中出现；
- 不使用“立即处理”“执行操作”“查看更多”等缺少对象的泛化文案。

## 10. 可访问性

- 文本与背景符合 WCAG AA；
- 焦点环清晰且不被裁切；
- tablist、环境选择、步骤、表格操作、弹窗、抽屉和菜单完整键盘可达；
- `aria-current` 表达当前路由，`aria-selected` 表达选中步骤/环境；
- 错误使用 `role=alert`，运行中状态使用 `role=status`；
- 动效遵循 `prefers-reduced-motion`；
- 不用只有图标、没有可访问名称的按钮。

## 11. 后台框架验收标准

- 导航分组、顺序和角色过滤与当前代码一致；
- 团队切换会刷新当前作用域且不串数据；
- 面包屑不显示原始项目或发布单长 ID；
- 主内容只有一个实心主操作；
- 桌面侧栏、移动菜单和搜索命中使用同一导航源；
- 部分数据失败时仍保留可用分区；
- 1440×1024、1280×800 和 390×844 三个视口无不可用控件或双重滚动；
- 所有目标扩展能力都标明 `DESIGN` 或 `BACKEND`，没有被误写为 `LIVE`。
