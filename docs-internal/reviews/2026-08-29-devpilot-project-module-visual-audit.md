## 结论

当前项目工作台已经形成可用且较一致的主干：项目 Header、项目级警告、基本事实、发布列表、配置导航、发布生命周期和部署证据均使用同一白底、轻边界和主次操作语言；本轮未发现阻断核心任务的 P0 视觉问题。

仍有 8 个 P1 信息架构或响应式问题。最需要继续收敛的是：域名能力存在双入口、证据 Drawer 仍有卡片套卡片、移动发布详情把当前任务推到过深位置、变量编辑器页脚在 390px 破坏操作层级，以及仍可直接访问的旧发布/创建路由与当前主流程不一致。

PMC068 已按最新明确要求纠正仓库信息架构：项目概览只展示默认折叠的 `高级信息` 标题；展开后使用扁平的 `仓库概览 / 最近仓库分析` 两段结构。仓库地址、托管/可见性、默认分支、当前 Commit 与验证时间直接可读；最近分析把真实状态、完成时间、阶段进度、识别数量和类型放在同一上下文，并只保留 `查看仓库分析` 入口。运行历史、阶段证据和识别到的变更仍位于独立 `仓库分析` 页；连接、凭据与默认分支维护仍归 `项目配置 → 仓库设置`，概览不再提供设置入口。

PMC069 已根据后续明确要求取代上述概览组合：折叠区改为范围明确、默认折叠的 `仓库详情`，展开后直接呈现只读仓库事实，不再混入分析运行；原 `环境与组件详情` 拆为 `环境 / 组件` 两个 Tab。最近一次真实组件识别摘要与完整分析入口进入组件上下文，运行历史与完整证据仍位于独立仓库分析页，连接和凭据维护仍位于项目配置。

PMC070 已进一步修正运行态与表格层级：仓库详情在每次进入项目概览时稳定默认折叠，不再由普通查询参数恢复展开；发布、环境、组件三个 Tab 的表格直接嵌入内容区，移除第二层圆角、外边框和阴影，仅保留工具栏、表头/行分隔及表格内部滚动。桌面和 390px 运行态均无页面级横向溢出。

## 设计上已经合理的部分

1. **概览层级清楚。** 基本信息使用无卡片事实网格，发布记录保持首要工作区，筛选位于左侧、部署记录入口位于右侧；没有多余页面标题或重复分隔线。
2. **高级信息与仓库职责清楚。** `高级信息` 默认折叠，展开后先读仓库事实，再读与解析产物绑定的最近运行摘要；没有设置维护入口、重复详情按钮或卡片套卡片。独立仓库分析页继续使用运行选择、所选对象、阶段证据、识别结果的连续阅读顺序。证据为 `pmc068-advanced-information-collapsed-desktop.png`、`pmc068-advanced-information-expanded-desktop.png`、`pmc068-advanced-information-collapsed-mobile-390.png`、`pmc068-advanced-information-expanded-mobile-390-final.png`。
3. **配置 scope 在移动端已收敛。** 环境与配置类型组成一个紧凑工具条，不再各占整行。
4. **部署列表滚动边界正确。** 桌面与 390px 的宽表均在表格视口内部滚动，不再把页面 `main` 撑宽或随 20 行数据无限增长。
5. **项目警告具备语义面。** 对象、问题、影响和精确去向处于同一浅色 warning surface，未用悬空图标或泛化“立即处理”。
6. **主要写操作的承载方式一致。** 创建发布、配置修订、变量、资源、策略、验证、域名流程均通过 Modal/Drawer 承载，直接 Select 只承担读取 scope。
7. **组件识别摘要与去向已重新归组。** `PMC071` 把“查看完整仓库分析”从内容区最右端移到“最近组件识别”标题旁；摘要与唯一查看动作不再被宽屏空白割裂，390px 可自然换行且保留 44px 触控高度。

## P1 问题

### P1-1 域名能力存在两个同级管理入口

- **证据：** `13-settings-domains-desktop.png`、`15-domains-development-empty-desktop.png`、`16-domains-production-desktop.png`、`37-domains-production-mobile-390.png`。
- **问题：** `项目配置 → 域名与入口` 与独立 `/domains` 页面都呈现环境选择和同一批入口对象，但布局、操作密度和上下文不同。用户无法判断哪个是权威维护面。
- **方向：** 保留一个编辑入口。建议项目配置拥有环境内配置，独立路由仅在需要跨环境比较或运维证据时保留；若无跨环境任务，直接重定向到配置子区。

### P1-2 独立域名页的环境选择仍单独占行

- **证据：** `15`、`16`、`37`。
- **问题：** 短 Select 悬在内容上方并留下大块空白，重复了本轮已在项目配置修复的 scope 问题。
- **方向：** 若保留该路由，把环境 scope 与对象标题/列表工具条合并；同时将这条规则纳入 workbench skill（配置页规则已覆盖，独立域名页尚未统一）。

### P1-3 域名证据 Drawer 仍呈现多层卡片

- **证据：** `17-domain-evidence-drawer-desktop.png`。
- **问题：** Drawer 外壳内再用多张完整圆角卡片分隔配置、DNS、TLS 与探测，导致每块内容都像独立主对象。
- **方向：** Drawer 内改为一个对象摘要、水平 Tab/分段导航和连续 `divide-y` 证据区；只对错误/阻断使用语义面。

### P1-4 部署证据 Drawer 的移动阅读路径过长

- **证据：** `20-24`、`40-deployment-drawer-mobile-390.png`。
- **问题：** 五区内容虽然真实完整，但 Drawer 内仍有外层内容卡和多组迷你事实卡；390px 下标题、Tabs、摘要卡和事实卡连续叠加，首屏无法快速抵达当前失败/验证证据。
- **方向：** 保留五区模型，去掉内层卡片外观；概览只保留一条运行摘要和关键结果，事实使用描述列表，错误/审计使用行式时间线。

### P1-5 移动发布详情在当前步骤前暴露过多共享输入

- **证据：** `41-release-build-mobile-390.png`，以及 `25-30` 的桌面步骤。
- **问题：** `发布输入` 在 390px 变为长的一列事实，长 SHA、来源和 Manifest 会占据多个屏幕，当前构建/部署任务被推迟。
- **方向：** 发布页级只显示版本、来源、目标链和证据完整性四个决策事实；其余技术字段折叠到同一详情 disclosure，并保持只出现一次。

### P1-6 变量编辑器移动页脚破坏操作层级

- **证据：** `43-settings-variables-editor-mobile-390.png`。
- **问题：** `复用配置到其他环境`、`取消` 与主提交并排时发生多行断裂，取消按钮也被压成两行，三个动作互相竞争。
- **方向：** 390px 使用两层页脚：主提交占满第一行；取消与复用放第二行，复用采用短标签或菜单。主操作必须保持唯一且完整。

### P1-7 生命周期当前/完成/未来状态区分不足

- **证据：** `25-30`、`41`。
- **问题：** 二级轨道中相邻多个步骤都使用高饱和蓝色圆点，容易把已发生、当前与可点击混为一类；未来一级箭头对比度又过低。
- **方向：** 已完成使用实心成功/中性完成标记，当前使用品牌蓝与清晰焦点环，未来使用满足对比度的灰色描边；颜色不能替代状态文案与真实证据。

### P1-8 兼容发布路由仍形成两套产品体验

- **证据：** `45-registered-releases-route-desktop.png`、`46-registered-publish-wizard-desktop.png`。
- **问题：** `/releases` 重复项目概览的基本信息与发布表，`/publish` 又保留一套独立卡片式三步创建体验，而当前主入口已经使用概览 Modal。直接访问时会看到不同信息架构和视觉语言。
- **方向：** 将兼容路由显式重定向到当前权威入口及等价状态；不要长期维护两套创建/列表界面。

## P2 问题

1. **验证表格重复不可用状态。** `12-settings-verification-desktop.png` 每行重复“不可用”，建议把环境级能力缺口放在表格上方一次说明，行内只显示该规则的最近证据。
2. **配置空态与修订入口脱节。** `09-11` 的空表下面仍有较大的无结构留白，`环境摘要与配置修订`像另一个孤立模块；建议与当前子区工具条合并。
3. **构建历史 Drawer 关键列截断过早。** `32-build-history-drawer-desktop.png` 的 Run 与时间同时被压缩；优先保留状态、短 Run、更新时间，完整 ID 放 tooltip/详情。
4. **域名新增 Modal 有轻微表面嵌套。** `18`、`38` 的上下文框、warning 与 Modal 外壳形成三层边界，可把上下文改成无边界描述列表，仅 warning 保留底色。
5. **移动共享 Header 首屏成本较高。** `33-44` 与 `50` 中项目身份、双按钮和项目 warning 合计占据大量首屏；这是项目级一致性带来的真实代价，可在二级深页压缩仓库元数据行，但不能删除项目阻断信息。

## 未能真实覆盖的状态

- 当前本地没有 queued/running 的 DeploymentRun 或 BuildRun，因此未验证真实运行态轮询下的视觉稳定性。
- 当前没有满足生产门禁的 Production ReleaseRun、生产 DeploymentRun、发布后验证或可执行回滚记录；没有伪造成功、恢复或回滚按钮。
- 当前浏览器只有 System Administrator 登录态，未覆盖非管理员的权限隐藏与禁用状态。
- 当前 Picshare 数据没有新的 pending repository suggestions；审核区截图展示的是已完成审核的真实结果。
- 英文只完成 message parity、type-check 与 build，未在本轮为全部 50 个截图状态逐页切换语言。

## 修复顺序建议

1. 先关闭两套域名入口与两套发布兼容路由的 IA 分叉。
2. 再扁平化域名/部署证据 Drawer，并修复变量编辑器移动页脚。
3. 最后收敛发布详情移动密度、生命周期状态语言和配置空态。
