# Devpilot

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- 团队管理员、项目负责人：在团队作用域内纳管项目、建立交付基线、配置环境并推动发布。
- AI Vibe Coding 用户：使用 AI 辅助生成应用或 Web 项目，并希望把代码仓库接入一条可配置、可发布、可追溯的交付流程。这一群体的技术背景和运维熟练度分布仍需用户研究确认。
- 开发与运维成员：处理版本、构建、环境配置、部署目标、资源、入口、日志、监控和恢复。
- 审批者与审计者：核对生产变更的风险、不可变输入、证据和审计记录。
- 只读观察者：查看项目、发布、运行证据和审计信息，不执行写操作。

## Product Purpose

Devpilot 是面向团队的软件交付控制台。它把代码仓库纳入统一的项目、环境、资源、发布、运行观测和治理流程，使用户能够从当前真实状态进入下一项可执行任务，并在生产变更前后保留可核对的门禁、审批、运行与审计证据。

成功意味着用户能够理解项目当前状态、明确阻断原因和下一步动作，并通过受保护的流程完成从仓库接入到生产发布、验证和恢复的完整交付。

## Positioning

当前实现支持的差异化机制是：把一个代码仓库转化为可审计、可配置、可发布、可恢复的交付对象，而不是把底层服务、Run、Manifest、Gate 等技术对象直接暴露成一组孤立后台页面。

以下定位仍待产品负责人确认：

- AI Vibe Coding 用户是否会成为第一优先级用户，还是与团队项目负责人并列的增长用户群；
- 私有化、自托管或内网交付是否属于核心产品承诺；
- 对外传播时是否以“AI 应用交付平台”替代当前更宽泛的“软件交付控制台”。

## Operating Context

- 用户在明确的团队、项目和环境作用域中工作。
- 主流程包括仓库连接与修订锁定、项目解析与人工审核、环境基线、配置与资源准备、发布单、构建与不可变制品、预发、生产预览与审批、生产部署、验证、版本与恢复。
- 高频操作发生在项目工作台、发布工作台、项目配置、域名与入口、部署运行、日志监控和审批审计之间。
- 桌面端承担完整操作；390px 移动端保留可理解的导航、状态、关键动作和响应式降级，不强行压缩宽表格。
- 产品提供中文和英文界面，领域状态与操作文案需要保持语义一致。

## Capabilities and Constraints

- 项目默认工作区先展示精简事实与默认折叠的只读仓库详情，再以 URL 驱动的同页 Tab 切换发布记录、环境和组件；组件上下文只展示最新真实组件识别概览并通往独立仓库分析页。项目配置作为 Header 次级入口进入已有环境的运行配置和域名入口；部署记录保留独立深链并从发布/运行上下文进入。
- 项目接入负责建立基线环境；项目配置只能选择已有环境，不能创建任意环境。
- 发布生命周期、准入、审批、并发保护、制品完整性、生产保护和审计真相由服务端持有，前端不得根据局部数据推断成功。
- 构建成功需要产生不可变 Manifest；生产应复用已通过预发的同一 Manifest。
- 生产预览输入变化或过期后必须重新预览；生产完成后才创建新的 EnvironmentVersion。
- 升级和恢复创建新的发布、部署和版本记录，不直接改写当前版本指针，也不删除历史。
- Manifest、digest、Run ID、输入哈希和原始 JSON 是技术证据，默认通过详情、抽屉或渐进披露呈现。
- 灰度、蓝绿、自动发布、真实流量切换、指标驱动自动终止和自动回滚 provider 目前不得表现为已可用能力。
- 自动识别或 AI 建议必须经过人工审核，不能静默修改项目事实。

## Brand Commitments

- 产品名称为 Devpilot。
- 产品文案应直接、具体，说明对象、原因、影响和结果；不使用装饰性 AI 话术、虚假实时感或无法兑现的能力描述。
- 视觉表达服务于操作决策、可信状态和证据阅读，不以技术复杂度或装饰效果证明产品先进。

## Product Principles

1. 从用户要完成的操作和当前阻断出发，不从后端对象目录出发。
2. 让状态、原因、影响和下一步动作处于同一上下文。
3. 对 Vibe Coding 用户逐步解释交付概念，同时为熟练团队保留高密度、低摩擦的操作效率。
4. 生产变更必须保留真实准入、审批、并发保护、不可变证据和可恢复历史。
5. 自动分析与 AI 建议辅助判断，但用户确认和服务端事实始终拥有最终权威。

## Accessibility & Inclusion

- 导航、筛选、环境选择、步骤、表格行操作、弹窗和抽屉必须可通过键盘到达并具有清晰焦点。
- 状态不能只依靠颜色表达；禁用或阻断动作必须同时说明原因和修复出口。
- 主要文本、状态、控件和反馈遵守 WCAG AA 对比度目标。
- 面向 Vibe Coding 用户的引导应使用业务语言和渐进披露，不要求用户先理解内部领域模型或基础设施术语。
