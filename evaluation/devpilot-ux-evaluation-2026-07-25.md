## 1. 执行摘要

### 1.1 总体判断
Devpilot 定位为「项目初始化与资源管控平台」，能力面**非常宽**：覆盖项目创建向导、应用服务与部署、服务器/站点/CDN/域名/反向代理等基础设施、资源申请—审批—交付—实例全链路、密钥中心、监控告警、日志中心、备份、执行治理、访问策略、操作审批、审计、团队、Git 集成、文档。后端状态机闭环完整（部署/资源/审批/备份/告警均有清晰枚举），RBAC + ABAC 权限模型、SSE 实时日志、多通道通知、回滚能力等"硬能力"都已具备。

**但"信息展示层"与"交互打磨层"明显落后于"能力层"**，典型反差：
- 后端 `ResourceInstance` 已把敏感字段单独拆出 `credentials`，但前端实例页把 `delivery` + `credentials` **全量明文铺开**，精心设计的 `sensitive` 标记在展示层失效；
- 后端 `resource-metrics` 已具备 CPU/内存采样，但监控页**只渲染状态点与采样数，不渲染真实数值、无图表**；
- 后端有 `GET /search` 之外的完整列表，但前端大量列表**无搜索/筛选/分页/下钻**；
- 审批能力存在但**无驳回理由、无审批人、审批与执行分离且无超时提醒**；
- 导航与页面标题/路由文案**多处不一致**；平台文档**首屏即"待补充"**。

一句话结论：**Devpilot 是一个"内核很强、外壳很糙"的平台。功能齐全度可与 Vercel/Railway/CODING 类比，但信息呈现、检索、反馈、安全展示与一致性距离"可用、好用"尚有系统性差距。**

### 1.2 核心问题 Top 10（按严重度）
| # | 问题 | 严重度 | 影响 |
| --- | --- | --- | --- |
| P0-1 | **资源实例页敏感凭证全量明文展示**（交付的连接串/密码无遮罩） | 🔴 高危 | 密钥泄露，直接违背"密钥中心按需 reveal"自身设定的安全基线 |
| P0-2 | **`auth/register` 无守卫（公开注册）+ 首 admin 无 seed/自助提权** | 🔴 高危 | 任意人可注册；生产首启需人工改库，存在安全与可运维断点 |
| P0-3 | **废弃/重复页面治理混乱**（cdn/domain 生成器、proxy 台账自称"只读"却可新增/模拟同步） | 🟠 高 | 用户迷失在功能重叠的页面，文案与行为自相矛盾 |
| P1-1 | 列表普遍**缺搜索/筛选/分页/下钻**（projects/applications/keys/instances/resources/监控/审计等） | 🟠 高 | 数据规模一大即不可用，找东西靠 URL 手改 |
| P1-2 | **监控/资源指标不渲染真实数值、无图表、无时间范围/聚合维度** | 🟠 高 | "监控"沦为状态清单，可观测性价值未释放 |
| P1-3 | **日志查看器缺归属列、行号、锚点、permalink、导出、分享** | 🟠 高 | 排障无法定位/分享/回溯，URL 不编码过滤条件 |
| P1-4 | **审批流过轻**：无驳回理由、无审批人、无二次确认、approved 长期不执行无超时 | 🟠 高 | 合规诉求（资源管控平台核心）不达标 |
| P1-5 | **成功反馈弱 + 表单规范不足**（必填无 `*`、无中文提示、提交后无 toast） | 🟠 高 | 用户不确定操作是否成功，必填易漏 |
| P2-1 | 导航 ↔ 页面标题 ↔ 路由文案多处不一致 | 🟡 中 | 心智负担、SEO/深链差 |
| P2-2 | 平台文档空壳（首屏"待补充"，仅 1 篇成文） | 🟡 中 | 新用户无引导 |
| P2-3 | 后端列表端点普遍缺分页（7/40 DTO）、错误码不统一、状态拼写 canceled/cancelled 混用 | 🟡 中 | 性能与前端一致性风险 |

### 1.3 竞品对标速览（详见第 6 节）
- **Vercel/Netlify**：部署"五要素 + 三态状态机"、每 PR 自动预览、变量按环境分列且密钥 write-once、日志行锚点可分享。
- **Railway/Render**：部署行内一键回滚（≤2 点击）、指标 per-instance/分位数、硬支出上限、可视化拓扑、保存变量三态（仅保存/重建部署）。
- **GitHub Actions/GitLab CI**：失败步骤自动展开+高亮+行链接、一键"重跑失败"、配置即代码实时校验+可视化。
- **CODING/云效/华为 CodeArts**：审批内嵌发布流+通知联动、DORA 开箱看板、按角色分层驾驶舱、企业微信/钉钉结果触达。

## 2. 评估方法与竞品基准

### 2.1 方法
1. **实际页面访问**：`curl` 抓取 `localhost:3120/` 公开着陆页与 `/dashboard`、`/docs`（返回 200，含全站侧边栏导航地图），其余受保护路由返回 `307 → /login?redirect=...`，据此确认鉴权在客户端发生。
2. **源码静态审计（只读）**：对前端 38 个路由页面 + 其 import 的组件，以及后端全部控制器进行逐文件审计，建立"功能/操作/数据项"清单（见附录核对表）。
3. **竞品调研**：派出 4 个 subagent 分别调研 Vercel/Netlify、Railway/Render、CI/CD（GitHub/GitLab/CircleCI/Drone）、国内平台（CODING/云效/华为/禅道/Gitee），提炼可引用的交互/链路/数据形式基准。
4. **交叉比对**：以前端展示 ↔ 后端能力 ↔ 竞品基准三方对照，定位"能力有但前端没呈现""前端有但文案/交互糙""安全/合规不达标"三类缺口。

### 2.2 竞品基准来源（4 份调研摘要）
- **基准 A（前端部署平台）**：部署事件流、预览环境评审内嵌、敏感变量 write-once + 日志脱敏、Log Drawer 评论回写 Git、request ID 可分享、菜单栏常驻状态。
- **基准 B（应用/后端部署）**：模板按成功率排序、deploy 行内一键回滚、变量自动探测 + 密封 + 环境隔离、日志键盘流 + 跨请求 ID、指标 per-instance/分位数、数据库双 URL、硬支出上限、全局搜索/可视化拓扑。
- **基准 C（CI/CD）**：有向图 + 依赖连线 + 矩阵展开、失败步骤自动展开+高亮+行链接、一键"重跑失败"、状态徽章外显、人工审批关卡+通知、配置即代码实时校验+可视化。
- **基准 D（国内研发协同）**：需求→代码→部署双向可追溯、审批内嵌发布流、DORA 开箱看板、企业微信/钉钉结果触达、按角色分层驾驶舱。

## 3. 平台总览与信息架构

### 3.1 平台定位（来自着陆页）
> 一站式交付你的全栈项目。全栈项目的控制面：项目创建与接入、资源申请与审批、站点与 CDN、监控告警、日志与执行治理。

着陆页列出了 6 大核心功能：项目创建向导、资源申请与审批、站点与 CDN、监控告警、日志中心、执行治理——与侧边栏实际功能相比偏少（实际还有团队、Git、文档、备份、执行策略、访问策略、操作审批、审计等），**着陆页未完整表达平台能力**。

### 3.2 功能地图（侧边栏导航 → 路由）
| 导航分组 | 侧边栏文案 | 实际路由 |
| --- | --- | --- |
| 仪表盘 | 仪表盘 | `/dashboard` |
| 项目 | 我的项目 / 应用服务 / 基础设施 / 服务器 | `/projects`、`/applications`、`/projects`（基础设施入口不明）、`/servers` |
| 站点 | CDN 配置管理 | `/cdn-configs` |
| 资源 | 运行态资源 / 资源申请 / 资源交付实例 / 资源连接 / 密钥中心 | `/resources`、`/resource-requests`、`/resource-instances`、`（资源连接无独立路由，疑并入 resources/keys）`、`/keys` |
| 运维 | 监控告警 / 日志中心 / 备份计划 | `/monitoring`、`/logs`、`/backups` |

除 `/dashboard`、`/docs` 外，其余 dashboard 路由（`projects / resources / logs / monitoring / sites / cdn / domain / execution-governance / operation-approvals / teams / servers / keys / backups / audit-events / access-policies / presets / git / resource-requests / resource-instances / resource-control / proxy-configs / cdn-configs / execution-policies / admin/resource-pools / admin/resource-types / applications`）均 `307` 重定向到登录页。登录页与注册页为独立 `(auth)` 布局。

## 4. 逐模块评估（主体）

> 每个模块结构：**现状 → 问题（带严重度）→ 更好预期（对比竞品）**。

### 4.1 项目与创建向导
**覆盖路由**：`/projects`、`/projects/new`、`/projects/import`、`/projects/[id]`、`/applications`

**现状**：项目列表用卡片网格展示名称/来源/纳管范围/技术栈/创建时间；创建向导为 5 步（基础信息→子项目→功能→资源→预览）并实时校验包名；导入页为分区表单；详情页含 6 个 Tab（概览/部署/环境/Webhook/资源/设置）。

**问题**
- 🟠 `/projects` 列表**无搜索/筛选/排序/分页**，卡片无删除/编辑行操作；来源与纳管范围文案由代码派生、未解释差异。
- 🟠 `/projects/new` 向导：跳步门"灰按钮"无解释；Step3 `LoadingState text=""` 空文案；子项目必选却**未标 `*`**且错误在底部易忽略；资源 4 种模式（skipped/manual/credential/instance/pool）复杂缺引导；`skipped` 删除配置**无确认**；生成成功**无 toast**（仅失败提示）；全局 store **无草稿，刷新即丢**。
- 🟠 `/projects/import`：`name` 必填却**不标 `*`**（与 new 页不一致）；`scope=resources` 时 DeploySection 不渲染但锚点导航仍列"deploy"→**锚点失效**；`provider=none`/空 repo 可提交；无进度指示。
- 🔴 `/projects/[id]` 详情：**Webhook Tab 仅有只读展示，无新建/编辑/删除入口**（功能盲区）；资源仅 MetricCard 计数、无明细跳转；健康度仅一个 Tag 无指标；主"部署"按钮跨页跳 `/applications` 与"部署历史"切 Tab **语义易混**；**无项目删除/归档**；`gitRepo` 字段不可点击。

**更好预期（竞品对标）**
- 列表补齐搜索框 + 筛选（按来源/范围）+ 排序 + 分页 + 行内删除/编辑（对标 Vercel 项目列表）。
- 向导每一步给出"为什么需要"的占位说明；必填统一 `*` + 中文提示；`skipped` 操作加确认；生成/导入成功显式 toast；**向导进度存草稿**（刷新可续）。
- 详情页 Webhook 提供完整的增删改；资源计数卡可点击下钻到明细；健康度给出具体指标（成功率/最近失败）；项目支持归档（软删）而非彻底消失。

### 4.2 应用服务与部署
**覆盖路由**：`/applications`

**现状**：5 张指标卡（应用数/服务数/环境数/部署次数/操作次数）；应用卡下钻到服务行，服务行可"部署/查看状态/日志/重启/回滚"；创建应用/服务/部署向导（dryRun/live 申请审批）。

**问题**
- 🟠 列表**无搜索/筛选 UI/分页**（仅 URL 参数过滤）；队列偏好（"队列中部署运行"）藏在三点菜单，**不易发现**。
- 🟠 部署向导成功仅回填、**无显式 toast**；"应用"与"服务"双创建入口**心智负担**；SLO 仅行内、无全局视图。
- 🟠 **无服务删除/停用**入口；危险回滚有 danger 标但**无二次确认**（仅依赖审批流，普通成员误点即触发流程）。

**更好预期（竞品对标）**
- 列表补搜索/筛选/分页；队列操作前置为可见按钮。
- 回滚等危险操作加二次确认弹窗（"确认回滚到 vX？将影响生产流量"），即便有审批流也应本地确认（对标 Railway 行内确认 + Render 健康检查失败自动回滚）。
- 提供"停止/停用"服务的显式入口与状态；SLO 提供全局视图（对标 Render Metrics 的 per-instance 下钻）。

### 4.3 基础设施：服务器 / 站点 / CDN / 域名 / 反向代理
**覆盖路由**：`/servers`、`/servers/[id]`、`/sites`、`/cdn`、`/cdn-configs`、`/cdn-configs/[id]`、`/domain`、`/proxy-configs`、`/proxy-configs/[id]`

**现状**：服务器管理（增/测连接/删）；站点管理（计划/同步/TLS/诊断/接管，能力最重）；CDN 配置台账 + 缓存刷新；域名/CDN 生成器（已声明废弃）；反向代理台账。

**问题**
- 🟠 `/servers`：表单必填**仅 HTML `required`，无 `*` 中文标记**；列表删除用 `deleteServerDescription`、详情页删除用 `deleteServerConfirm`，**同一操作两段文案不一致**。
- 🟠 `/servers/[id]`：关联代理配置名为纯文本 **不可点击跳转**；编辑保存**无成功 toast**；host/port 创建后不可改，与"基本信息可编辑"暗示不一致。
- 🔴 `/sites`：`filterHint` 写"输入域名或项目筛选"，但**页面无搜索框**（仅 URL 参数过滤）；主域名链接**恒为 `http://`** 即便已启用 TLS；表单庞大**无分区标题**；Let's Encrypt 邮箱为条件必填但**无前端校验/`*`**；无分页；"站点操作加入队列"文案晦涩无 tooltip。
- 🟠 `/cdn`（废弃）：整页已声明废弃却仍完全可用、无强引导；错误同时 inline ErrorBanner 与结果区红字**重复展示**；URL 配置值 `truncate` 且**不可单独复制**。
- 🔴 `/cdn-configs`：**缓存规则 UI 无法创建/编辑**（新建表单无该字段，详情编辑仅 name+origin），属功能缺口；卡片"清除缓存"与详情"刷新全部缓存"**文案不一致且均无二次确认**（真实 CDN 写操作）；无状态指示。
- 🟠 `/domain`（废弃）：同 cdn 生成器——废弃却可用、与站点能力重复。
- 🟠 `/proxy-configs`：横幅称"只读台账"却仍提供"添加配置"且**同步为"模拟实现"**（文案自相矛盾、可能误导）；域名纯文本不可复制；权重仅详情显示。

**更好预期（竞品对标）**
- **废弃页面治理**：要么真正移除（301 到 sites），要么在首屏强引导"此功能已并入站点"。禁止"自称只读却可写"的矛盾态（对标 Vercel 把预览默认登录访问之类的"行为即文档"）。
- 站点补真实搜索框；主域名链接按实际协议（`https://` 当 TLS 启用）；表单按分区标题组织；条件必填统一 `*` + 校验。
- CDN 缓存规则提供完整 CRUD；"清除缓存/刷新"统一文案 + 二次确认 + 操作审计（对标 Vercel/CDN 控制台的明确写操作确认）。
- 所有域名/连接串/上游地址提供一键复制；关联项（代理配置）可点击跳转。

### 4.4 资源管控：申请 / 审批 / 实例 / 密钥 / 类型 / 池 / 预设
**覆盖路由**：`/resources`、`/resource-control`、`/resource-requests`、`/resource-instances`、`/keys`、`/admin/resource-pools`、`/admin/resource-types`、`/presets`

**现状**：资源申请→审批→交付→实例全链路状态机清晰；密钥中心按需 reveal 是安全范本；资源类型可配置审批/交付模式与敏感字段标记。

**问题**
- 🔴 **脱敏两极分化（最严重安全隐患）**：`/keys` 是范本（列表不展示值，点击 reveal 才取明文、复制即清）；但 `/resource-instances` 的 `delivery` **把 `credentials` 与 `delivery` 一并全量明文铺开**，`hasCredentials` 仅一个标签，**无任何遮罩/查看确认**——资源类型里精心设计的 `sensitive` 标记在展示层完全失效。
- 🔴 `/resource-control` 的"连接查询面板"**不回显连接串或查询结果**（后端 `preview.rows`/`redaction` 已具备却未渲染），用户交付后找不到"去哪看连接信息"的显眼入口。
- 🟠 `/resources` 与 `/resource-control` 两个"资源"入口**命名易混淆**；列表无筛选/搜索。
- 🟠 `/resource-requests`：审批**无理由输入、无审批人、无二次确认**；`provisioning` 的 `reason/boundary` **不再悬浮展示**（信息丢失）；MetricCard 计数**不可点筛选**。
- 🟠 `/keys`：无搜索/筛选；`store` 弹窗 `value` 明文录入，保存后未提示"已加密存储"。
- 🟠 `/resource-types`：`sensitive` 标记与实例页明文**未闭环**；`key` 新建后不可改易误填。
- 🟡 `/presets`：导出为明文 JSON（可能含密钥变量）**无脱敏提示**。

**更好预期（竞品对标）**
- **立即对齐脱敏**：实例页 `delivery` 中 `sensitive` 字段默认遮罩（••••），点"查看"才 reveal，与密钥中心一致（对标 Vercel 敏感变量 write-once + 构建日志自动脱敏）。
- 提供统一的"连接信息"视图（资源管控页回显脱敏后的连接串，点击 reveal 看明文 + 复制），让"交付后去哪看"有确定入口。
- 审批表单增加"驳回理由"（必填当 reject）与审批人展示；approved 长期未执行加超时提醒/自动撤回（对标 国内平台审批内嵌发布流）。
- 两个"资源"入口合并或明确语义区分；MetricCard 可点击下钻到对应筛选列表。

### 4.5 运维：仪表盘 / 监控 / 日志 / 备份
**覆盖路由**：`/dashboard`、`/monitoring`、`/logs`、`/backups`

**现状**：仪表盘聚合待办+指标+近况；监控含资源指标面板 + 告警事件/规则/静默/通知通道 4 Tab；日志为统一浏览器（历史检索 + SSE 实时 tail）+ 流管理；备份为计划/运行管理。

**问题**
- 🟠 `/dashboard`：指标卡**非链接、无下钻**；"24h 失败部署"链接到通用 `/applications` 而非已过滤视图；`runningDeployments` 合并 queued+running 语义模糊；无刷新指示/时间范围；近况仅 6/5 条且无"查看更多"分页。
- 🔴 `/monitoring`：资源指标面板**只显示状态+采样数，未渲染 CPU/内存等真实数值**（类型已具备）；**无时序图、无聚合维度选择器**（latest/average/max 标签 UI 未用）；告警事件所带 `project/server/site` **字段未展示、无到规则/资源链接、无 resolve 动作**；`condition` 为**裸 JSON** 易错；`severityFilter` 为逗号自由文本无校验；`resource/backup` 类规则**无法在 UI 绑定具体资源**（功能缺口）；各 Tab 无统一时间范围/筛选；单次加载触发 12 个并行 API。
- 🔴 `/logs`：查看器**只显示 level/message/time，不显示 project/server 等归属列**（`LogEntry` 已含却未用）；**无行号、无行锚点/permalink、无复制、无法分享某条日志**（URL 不编码 stream/query/level/timeRange）；无导出；Live 仅保留最近 100 条无回溯；时间范围**无绝对区间**；策略/运行等管理功能藏进抽屉；注入级别缺 trace/fatal/debug；无流内搜索。
- 🟠 `/backups`：`destinationType` **硬编码 `local` 但表单无对应控件**（目标类型对用户不可见）；"生成计划/运行/恢复"实质发 `dryRun:true`，**按钮语义像"立即备份"实为"计划"**，与高警示 danger 文案不符；无计划删除/编辑、无调度(cron)展示、无备份大小/进度；阻塞/失败原因无逐计划明细。

**更好预期（竞品对标）**
- 监控：资源指标渲染**真实数值 + 时序折线图 + 时间范围(15m/1h/6h/24h) + 聚合维度(latest/avg/max) 选择器**（对标 Render Metrics、Grafana）；告警事件列出归属资源并可点击下钻、提供"resolve/确认"动作；`condition` 提供可视化构建器或至少模板校验；补齐 resource/backup 类规则的资源绑定。
- 日志：表格补"来源/项目/服务"归属列；**每条日志带行号 + 点击生成 permalink（#L6，可分享）**；支持按文本搜索、按级别/来源过滤、导出 CSV；Live 支持回溯与持久会话（对标 GitHub Actions 行级 permalink、Render 日志键盘流 `/` 聚焦搜索、requestID 追踪）。
- 备份：目标类型纳入表单；区分"立即执行(live)"与"仅计划(dry-run)"并明确标注；提供计划编辑/删除、调度展示、备份大小与进度条、失败原因明细。

### 4.6 治理：执行治理 / 执行策略 / 访问策略 / 操作审批 / 审计
**覆盖路由**：`/execution-governance`、`/execution-policies`、`/access-policies`、`/operation-approvals`、`/audit-events`

**现状**：执行治理观测后台任务（主管/作业/租约）；执行策略为命令白/黑名单正则模板；访问策略为 ABAC 允许/拒绝规则；操作审批为 pending→approved→执行；审计事件可筛选。

**问题**
- 🟠 `/execution-governance`：导航"任务队列治理" vs H1"执行治理"不一致；scope 摘要对人类不友好；自述"一般无需关注"却置于治理区首位。
- 🟠 `/execution-policies`：正则是高门槛，**无实时校验/测试**；作用域"项目留空=团队全局"易混；无字段级校验/错误提示。
- 🟠 `/access-policies`：多维组合规则对普通用户复杂，卡片信息密但缺"匹配顺序/冲突解决"说明；effect 与 riskLevels 关系不直观。
- 🔴 `/operation-approvals`：批准/拒绝**无驳回理由输入**（`reviewComment` 字段存在但未采集）；审批后需再手动"执行"，approved 长期不执行**无超时/提醒**；仅 status 一个筛选，无搜索/批量。
- 🟠 `/audit-events`：**可检索性弱**——仅 3 下拉，无关键词/时间范围/执行人搜索，难以回溯特定操作；无详情抽屉；runRef 显示不可点；actor 无链接。

**更好预期（竞品对标）**
- 审批：驳回必填理由；审批与执行可合并为"批准即执行"或保留分离但加超时自动提醒/撤回（对标 GitHub Environments 的 required reviewers + wait timer）。
- 策略：正则提供"测试此规则"沙盒；作用域提供显式选项而非"留空=全局"；卡片补匹配顺序与冲突解决说明。
- 审计：补全文检索（关键词/时间/执行人）、详情抽屉、可点击的 runRef 与 actor，支持导出（对标 GitLab 审计事件）。

### 4.7 团队与协作：团队 / Git 集成 / 平台文档
**覆盖路由**：`/teams`、`/teams/[id]`、`/git`、`/docs`

**现状**：团队 CRUD + 成员管理（owner/admin/member）；Git 连接账号与仓库；文档站（侧栏 + 查看器）。

**问题**
- 🟠 `/teams`：删除团队**无级联资产（成员/项目归属）警告明细**；`/teams/[id]` 添加成员**不可指定 owner**，**owner 转移路径不明确**；移除最后 owner/自己无防护提示。
- 🟠 `/git`：连接后仓库需手动"查看仓库"才加载（非自动）；无展示已授权范围/权限；token 错误仅 root banner。
- 🔴 `/docs`：**首屏默认加载 overview 占位文档，用户进入即见"待补充"空文档**；仅 1 篇正式文档（execution-policies），其余占位；侧栏无"已完成/待补充"标识；选中态无 URL 同步（不可深链/分享）。

**更好预期（竞品对标）**
- 文档：首屏应呈现"快速开始"等有效内容而非空占位；每篇标注完成度；选中态同步 URL 支持深链（对标 Vercel/Netlify 文档站）。
- 团队：owner 转移提供显式流程；删除团队弹窗列出将受影响的资产；移除最后 owner 拦截并提示。
- Git：连接后自动拉取仓库；展示已授权范围；token 错误就近提示。

### 4.8 鉴权与安全（API 层）
**覆盖路由/接口**：`auth/*`、`teams/*`、`audit`、`server-agent/*` 等

**问题**
- 🔴 `POST /auth/register` **无守卫（事实公开注册）**，任意人可注册；首 admin **无 seed/自助提权路径**（需手动改库），生产首启存在安全与可运维断点。
- 🟡 状态枚举拼写不一致：`ResourceRequest` 用 `canceled`（美式），`OperationApproval` 用 `cancelled`（英式），跨域状态机拼写不统一，前端映射易错。
- 🟡 列表端点普遍缺分页（仅 7/40 DTO 含分页参数）；错误码不统一（无业务 ResultCode 封套）；无全局搜索、无 DORA/研发效能度量接口。
- 🟡 `/server-agent/*` 为高权限执行面，依赖 token/lease，建议审计其防伪造强度。

**更好预期（竞品对标）**
- 注册默认关闭或加邀请码/审批；提供首 admin 的 seed 或自助提权流程（对标企业平台的"初始化管理员"向导）。
- 统一状态枚举拼写、统一分页参数（`page/pageSize`）、统一业务错误码封套。
- 补齐全局搜索接口与 DORA 四指标（部署频率/变更失败率/恢复时长/交付时长）看板（对标 华为 CodeArts/云效 Insight）。

## 7. 优先级改进路线图

### P0（安全 / 阻断性，建议立即处理）
1. **资源实例页敏感凭证脱敏**：`delivery` 中 `sensitive` 字段默认遮罩 + reveal（与 keys 对齐）。【最高优先级，直接防泄露】
2. **注册网关 + 首 admin 初始化**：关闭公开注册或加邀请；提供首 admin 引导，消除生产首启断点。
3. **废弃页面治理**：cdn/domain 生成器移除或强引导；proxy 台账禁止"自称只读却可写"的矛盾态。

### P1（核心体验，建议 1–2 个迭代）
4. 列表统一组件：搜索 + 筛选 + 排序 + 分页 + 计数卡下钻（覆盖 projects/applications/keys/instances/resources/监控/审计）。
5. 监控真实数值 + 时序图 + 时间范围/聚合维度；告警事件补归属/下钻/resolve。
6. 日志补归属列、行号、permalink、搜索、导出、分享。
7. 审批补驳回理由 + 审批人 + 超时提醒；危险操作（回滚/清除缓存）二次确认。
8. 表单必填 `*` + 实时校验 + 成功 toast；instance/监控等缺失字段补齐。

### P2（打磨，持续改进）
9. 导航/标题/路由文案一致性；着陆页补全能力地图。
10. 平台文档从"待补充"填充"快速开始"等有效内容 + 深链。
11. 后端统一分页参数、错误码封套、状态拼写；补全局搜索与 DORA 看板。
12. 团队 owner 转移/删除级联提示；Git 自动拉取仓库与授权范围展示。
