## 一、预发发布 / 生产发布：布局与内容展示

### 问题

1. **阶段卡片违反 workbench 契约**。契约明确「不要把 staging/production 做成两张大摘要卡」（workbench-contract.md:21），当前两卡宽窄不一（约 60/40）、中间箭头含糊，视觉重量远超其信息量（只有名称+状态）。它们实际承担的是「视图切换器」职责，但形态像对比看板。
2. **阻断 banner 与主操作矛盾**（见上表）：banner 称阻断 3，「发布到生产」却可点。门禁若不能约束按钮，就是装饰（design-lessons：不影响执行路径的策略是文档不是行为）。
3. **决策阶段指针停滞**：预发已完成，banner 仍「当前决策 · 预发（Staging）发布 · 当前准入阻断」，用户无法判断这 3 个阻断到底挡的是哪一步。
4. **meta 行冗余**：「真实执行阶段」与标题徽章「预发（Staging）发布」逐字重复；「候选代码 master @ 8e7c465d」与右栏「精确 Commit」重复；「当前环境版本」把 `Staging · 0.0.1 · Production · 暂无` 两个环境挤进一个字段。
5. **生产视图内容单薄且 raw ID 平铺**：「制品」是近全长的 sha256，「预发验证」是 raw DeploymentRun cuid（`cmsn5pyqs01bd3nfoljnee97t`），「生产状态 等待中」+「尚无生产发布运行」+「预发验证通过后可发布」三句话与 banner 阻断态关系不清（rel-production.png）。
6. **步骤 03 图标误导**：部署已完成，图标却是半圆环（进行中的视觉语言）。
7. **预发「发布」按钮零反馈**：已完成环境下该按钮语义不明（重部署？），点击无任何反馈。

### 优化建议

- 阶段切换改为紧凑分段控件（`● 预发发布 已完成 ｜ ○ 生产发布 等待中` 一行式），省下的纵向空间给执行内容；符合契约「环境是范围选择器」。
- banner 与操作强绑定：阻断 > 0 时「发布到生产」禁用 + 原因 + 「前往基线检查」跳转；banner 决策阶段指向真实当前阶段（预发完成后应指向生产准入）。
- meta 行砍到 3 项：发布版本号、候选代码、最近运行；环境版本拆成 `预发 0.0.1 / 生产 暂无` 两个独立小字段或移入各阶段区。
- 生产视图的「制品」「预发验证」改为业务语言 + 折叠（`BuildRun #10 制品 · sha256:32bf01d5…`、「预发部署 #10 · 已完成」），raw ID 进 details。
- 已完成阶段的「发布」按钮改为「重新部署」并带确认弹窗 + 影响说明；或禁用 + 原因。
- 已完成步骤一律实心 ✓。

## 二、前置检查 / 构建 / 部署面板

### 问题

1. **右栏与步骤详情大面积重复**（最突出的结构问题）：
   - 步骤 03 详情（已完成 1s · 时间 · 日志 · 技术部署 · 业务验证 · Manifest Digest）与右栏「部署信息」**逐字段重复**；
   - 步骤 02 详情（构建成功 BuildRun #10 · Commit · Manifest Digest）与右栏「构建信息」同样重复；
   - Manifest Digest 全长 sha256 同屏出现 3 次（步骤详情、构建信息、部署信息）。
2. **前置检查（步骤 01）**：
   - 阻断计数 3 vs 5 两处矛盾（ROD-1 残留）；
   - 每组右侧「不可用」badge 语义恐吓且不解释（是检查没跑？证据缺失？服务不可用？）；
   - 描述行术语堆叠（「缺少精确 Commit、默认 HEAD、基线与合并树的真实 Git 证据」），且 raw ISO 时间戳（ROD-5 返工项）；
   - 基线三小卡（主分支仓库/预发基线/生产基线）只有「已就绪 + 项目接入时锁定」，无锁定 commit/时间，信息太薄无法支撑判断。
3. **badge 语义**：「证据不可用」（听着像故障，实为未采集）、「待完成（不阻断）」（括号补充说明是善意但形态不统一）。

### 优化建议

- **去重（结构级）**：右栏改为「当前阶段上下文」——只在查看非当前步骤/阶段时展示对应摘要；查看当前步骤时右栏让给「门禁决策摘要 + 下一步操作」。至少做到：步骤详情存在时，右栏同名字段不再重复。
- Manifest Digest 等哈希全场统一短哈希（前 12 位）+ 点击复制 + details 折叠，同屏至多出现 1 次。
- 「不可用」改为「未执行/证据缺失」等准确状态词 + 一句话原因 + 「重新检查」内联动作；描述行翻译为业务语言（「缺少真实 Git 证据（精确 Commit / 基线合并树）」）。
- 基线卡片补锁定时间与 commit 短哈希。
- badge 文案中性化：「证据不可用」→「未采集」，「待完成（不阻断）」→「可选验证 · 未完成」。

| 字段 | 必要性判定 | 处理建议 |

| Manifest Digest | 非决策 | 折叠 |

| 日志 | 必要 | 保留 |

### 构建历史抽屉（当前列：BuildRun ID/revision、Commit、结果、Manifest、耗时/时间）

- **BuildRun ID 列**：raw cuid 为主、`#10` 为辅 —— 应反转，cuid 折叠；该列实际是「修订号」。
- **结果列**：失败原因 raw 枚举（`ARTIFACT_SECRET_…`/`BUILD_COMMAND_F_…`/`ARTIFACT_UNSAFE_…`）未本地化、截断后不可读 —— 翻译 + 完整原因 title/展开。
- **Manifest 列**：raw cuid + sha —— 非决策信息，整列折叠进行详情。
- **缺失**：操作列（查看日志 / 用此构建部署）——历史不可操作则只有观赏价值；状态筛选（9 失败 1 成功混排）。

### 部署历史抽屉（当前列：部署运行、构建/Manifest、执行结果、验证结论、耗时/时间）

- **三处 raw cuid**（DeploymentRun、BuildRun、Manifest）+ provider raw key `local-filesystem-v1` —— 全部映射/折叠，此抽屉是 ROD-4 修复未覆盖的回流点。
- **验证结论列**最有业务价值（技术部署/业务验证双结论），保留并提为主列。
- 顶部橙色「部署目标与当前 Provider 不匹配」无解释无动作 —— 补一句影响说明 + 修复链接。
- 半屏宽抽屉只装 1 行数据，大片空白 —— 宽度自适应内容（~560px）或行内展开替代抽屉。
- 同样缺操作列（日志/重部署）与筛选。

### 日志弹窗

- 标题含完整 DeploymentRun cuid；字段区 DeploymentRun ID / BuildRun ID / Manifest ID / Manifest Digest **四个全长 ID 平铺** —— revision #10 + 短哈希足够，全长 ID 全部进 details。
- 「技术部署证据」raw JSON（含拼接 projectId 的 deploymentUri）—— 结构化字段渲染，原始 JSON 折叠。
- 「完整部署日志」区本身 OK（逐行文本）。
