## 第一部分：评审方案

### 1.1 评审维度模型（用户指定评审点 × 调研框架的合并）

用户指定维度（内层）+ 调研框架 10 维度（外层）合并为 **8 个一级评审维度**，避免交叉重复：

| # | 一级维度 | 合并来源 | 本报告评审点（可检查、可打分） |
| --- | --- | --- | --- |
| D1 | 流程合理性与流畅性 | 用户"整体流程合理性和流畅性" + 框架§2 | 端到端闭环、golden path 引导、审批闭环、异步任务恢复、中断续作、撤销与回退 |
| D2 | UI 可用性 | 用户"UI 可用性" + 框架§3§6 | 四态齐全（加载/空/错/成功）、防错与禁用解释、危险操作分级确认、表单校验即时就近 |
| D3 | UI 可读性与内容展示 | 用户"UI 可读性/内容展示合理性" + 框架§5 | 技术 ID 不外泄、术语一致、业务语言优先、错误三段式、信息密度与层级 |
| D4 | 模块可用性（信息架构） | 用户"项目模块的可用性" + 框架§1§8 | 导航=标题=路由一致、深链可还原、跨模块跳转断点、角色路径、模块职责边界 |
| D5 | 一致性与组件选型 | 框架§4 | 同类信息同类组件（表格 vs 卡片）、状态映射统一、页面骨架统一、时间格式统一 |
| D6 | 安全呈现 | 框架§6 + 平台特性 | 生产标识、密钥遮蔽、变更 diff 预览、高危操作影响说明 |
| D7 | 可观测性呈现 | 框架§7 | 信噪比、证据与门禁可读性、关联下钻 |
| D8 | 可访问性与性能感知 | 框架§9§10 | 键盘可达、焦点管理、对比度、骨架屏、大列表 |

### 1.2 评分与定级

- 每条缺陷按 0–4 打分（对齐 Nielsen 严重度）：1=表面、2=次要、3=主要、4=灾难
- 优先级：P0=严重度 4 或涉及生产安全/核心流断链；P1=严重度 3 或高频路径的 2 分问题；P2=打磨类
- 缺陷记录五字段：**模块 / 维度 / 评审点 / 证据（截图）/ 评分定级**

### 1.3 评审执行方式（本次实际执行）

- 模块 × 维度矩阵：六子域为行，D1–D8 为列，逐格检查
- 每条核心流程以"任务"为单位走查：创建发布、切换版本、绑定资源、审核识别建议、添加域名入口、查看部署日志
- 所有结论以真实渲染截图为证据；交互类结论（禁用态、弹窗、跳链）经 DOM 验证

## 第二部分：逐域评审（问题 + 解决方案 + 设计稿）

> 问题编号规则：域首字母 + 序号。每条含【维度】【严重度】。

### 2.1 项目版本管理（项目配置 → 版本）

**现状**：环境单选 + 当前环境版本表 + 已有版本表 + 右侧发布证据栏；版本切换走受审计部署路径（设计正确）。

| # | 问题 | 维度 | 严重度 | 证据 |
| --- | --- | --- | --- | --- |
| V1 | 版本名称与版本号重复显示（"0.0.1 / 0.0.1"），右侧证据栏顶部同样重复 | D3 | 2 | `cfg-版本.png` |
| V2 | "切换版本"按钮禁用但**无任何原因说明**（DOM 验证 `disabled=true`，无 tooltip/aria-describedby） | D2 | 3 | DOM 验证 |
| V3 | 环境选择器显示 "Production (production)"，名称与 raw key 冗余并列 | D3 | 1 | `cfg-版本.png` |
| V4 | dev 环境有多次已完成部署（部署记录可见），版本 tab 却显示"尚无可追溯环境版本"——**版本模型与部署事实脱节**，用户无法解释 | D1 | 3 | `cfg-version-dev.png` vs `wb-deployments-view.png` |
| V5 | 顶部警示条"生产环境缺少可用入口"在查看 dev 环境时依然显示，环境上下文错位 | D4 | 2 | `cfg-version-dev.png` |
| V6 | **1280px（13" 笔电）下"已有版本"表格列重叠**：发布证据/创建时间/状态与操作列文字互相叠压，"待生产审批"状态被遮盖不可读 | D8 | 3 | `settings-1280.png` |

**解决方案**（设计稿：`mockups/02-version-management.html`）：

1. 版本主文案只出现一次：版本号为主标题，名称作副标题；右侧证据栏不重复版本号
2. 禁用动作必须解释：`切换版本` disabled + tooltip "该版本尚未通过生产发布审批，通过后才能切换"（通用规则：任何禁用按钮必须可悬停出原因，写入组件规范）
3. 环境选择器只显示"生产"（raw key 移入技术详情）；warning 条与当前选中环境联动（看 dev 时不提示生产的问题，或标注"（生产环境）"）
4. V4 需要产品决策：要么部署即产生版本记录（推荐，消灭"部署了但没版本"的认知裂缝），要么空态文案改为"该环境的部署早于版本管理机制，尚无可追溯版本"给出解释
5. V6 响应式：1280px 下表格启用横向滚动或列优先级收缩（操作列固定、证据/时间列折叠），禁止文字叠压；纳入视觉回归测试基线

### 2.2 资源绑定管理（项目配置 → 资源绑定）

**现状**：计数 chips + 修订信息 + 资源引用选择器 + 说明文字。

| # | 问题 | 维度 | 严重度 | 证据 |
| --- | --- | --- | --- | --- |
| R1 | 8 个计数 chips（服务器/站点/托管资源/资源实例/密钥/CDN/资源申请/部署次数）大多为 0，噪音淹没唯一的有效信息"1 服务器" | D3 | 2 | `cfg-资源绑定.png` |
| R2 | "当前生效 · 修订 R1 · 46a28a2d" raw 修订 ID 直接上屏 | D3 | 1 | 同上 |
| R3 | "MVP 不在项目页申请或创建云资源…"内部开发免责声明直接面向用户 | D3 | 2 | 同上 |
| R4 | "资源引用与共享范围"只有一个下拉 + 添加按钮，无可选项预览、无已绑定列表（"没有资源引用"仅一行小字），交互模型不完整 | D2 | 3 | 同上 |

**解决方案**（设计稿：`mockups/04-resource-binding.html`）：

1. 摘要行只渲染非零项："已绑定 1 台服务器 · 0 个资源实例"，0 项进"展开全部"披露
2. 绑定关系用**表格**呈现（资源/类型/绑定方式/状态/操作），而不是计数 chips + 单行提示
3. 修订 ID 移入底部折叠"技术细节"；MVP 免责声明删除或改写为用户语言："绑定后部署时可引用该资源连接信息；解绑不会释放资源实例"
4. 添加引用改为完整选择卡片：可选资源列表（含类型/来源/状态），选中即见预览再确认

### 2.3 项目识别管理（项目信息 → 仓库解析与审核）

**现状**：项目组件表 + 折叠的"仓库解析与审核"区，建议卡片带 接受/编辑后接受/忽略 三选 + 技术证据披露 + 审计入口。**这是六域中设计最完整的区域**，渐进披露和"建议需审核才落库"的原则执行到位。

| # | 问题 | 维度 | 严重度 | 证据 |
| --- | --- | --- | --- | --- |
| A1 | 完整 40 位 commit SHA 直接展示在"项目仓库来源"卡片 | D3 | 1 | `repo-analysis-3.png` |
| A2 | 严重度徽章用英文 "high" / "medium" | D5 | 1 | 同上 |
| A3 | 已完成审核的运行仍显示 接受/忽略 radio 组（只读但形似可交互），"这次运行的建议已完成审核"与控件同在，认知矛盾 | D2 | 2 | 同上 |
| A4 | 项目组件表的"配置已变更"标记与下方审核项之间没有跳转链接，用户需自行展开寻找对应项 | D1 | 2 | `repo-analysis.png` |
| A5 | "仓库解析与审核"默认折叠且仅在"主动解析"时才有内容——识别入口深，新用户难以发现这个能力 | D4 | 2 | `repo-analysis.png` |

**解决方案**：

1. SHA 缩短为 8 位 + 点击复制完整值（复用全站 Copyable 组件）；徽章中文化（高/中/低）
2. 已审核运行的 radio 组改为只读结论徽章（"已接受 / 已编辑接受 / 已忽略"），不再渲染表单控件
3. 组件表"配置已变更"加锚点链接直达对应审核建议卡
4. 在 项目信息 页给"仓库解析"一个显性入口（如组件表上方"重新解析仓库"次级按钮 + 最近解析时间），折叠区保留但不再是唯一入口

6. 导航类动作用 `<a>` 渲染；系统级门禁异常与用户待办分区展示
