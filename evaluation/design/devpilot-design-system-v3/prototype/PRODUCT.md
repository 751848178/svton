# Devpilot vertical slice

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React + Vite prototype, isolated from the production application.

## Users

- AI Vibe Coding users who need a plain-language path from a generated repository to a trustworthy release.
- Project owners and operators who need dense, auditable delivery facts and precise repair actions.
- Approvers and auditors who inspect production inputs, gates, evidence, and recovery history.

## Product Purpose

Show how Devpilot turns one repository into a configurable, releasable, auditable, and recoverable delivery object. The prototype succeeds when a new user can follow the delivery path and an experienced operator can inspect exact evidence without losing context.

## Positioning

Devpilot is a guided delivery control plane: AI may explain and stage proposals, while users and server-owned facts remain authoritative.

## Operating Context

The Picshare journey connects a repository, reviews analysis, configures production, creates a release, resolves a production blocker, deploys the accepted artifact, and inspects evidence.

## Capabilities and Constraints

- Project destinations remain `项目信息 / 发布 / 项目配置 / 域名与入口 / 部署记录`.
- Project configuration selects existing environments only.
- AI explanations never imply that production state changed.
- Manifest, digest, Run IDs, and raw evidence stay behind progressive disclosure.
- All values are deterministic prototype fixtures based on confirmed Devpilot domain contracts.

## Brand Commitments

- Product name: Devpilot.
- Copy names the object, problem, impact, and outcome directly.
- Visual hierarchy serves operational decisions rather than decorative AI styling.

## Product Principles

1. One current decision per page.
2. Explain first, disclose technical evidence on demand.
3. Keep repair actions beside their cause.
4. Let AI propose; let users review; let the server confirm.
5. Create density through alignment, not smaller type.

## Accessibility & Inclusion

Keyboard-accessible navigation and controls, visible focus, non-color status cues, WCAG AA contrast, and a readable 390px mobile fallback.
