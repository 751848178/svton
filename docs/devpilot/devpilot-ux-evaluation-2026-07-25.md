## 1. 执行摘要

Devpilot 是一个**功能版图野心很大**的平台：34 个前端路由、40 个后端 controller、52 张数据表，覆盖项目脚手架、部署、站点/CDN、资源申请审批、监控告警、日志、备份、执行治理、审计九大域。其中**安全治理设计是明显亮点**——dry-run 预览、风险分级操作、输名称确认（type-to-confirm）、审批链、审计闭环，工程素养超过多数同类自研平台。

但本次评估发现 **5 个 P0 级阻断问题** 和约 **60 个 P1/P2 问题**，集中在四个层面：

| 维度 | 评分（5 分制） | 一句话结论 |
|---|---|---|
| 功能覆盖度 | ★★★★ | 版图完整，但存在 13 组"有后端没按钮"的能力断点 |
| 交互合理性 | ★★★ | 核心链路（创建/部署/审批）设计优秀，但反馈一致性、安全等级倒挂、废弃页收口拉低整体 |
| 信息完整性 | ★★★ | 治理域信息过剩、项目/部署域信息不足，两级分化 |
| 可用性与稳定性 | ★★ | 无限加载无兜底、日志查询契约破损、后台任务可拖垮全站，是最大短板 |

**最关键的 5 个 P0（修复优先级最高）**：

1. **页面级无限"加载中..."无任何超时/错误/重试兜底**——评估中真实发生：资源申请、资源实例、资源连接、密钥中心 4 页同时挂起 60~90 秒不恢复，最终连最初秒开的页面也沦陷；创建向导在评估中途同样挂起。API 直连探测响应 5~7ms 正常，问题出在 Web 服务端取数挂起。一个卡死的后台任务即可造成全站性可用性事故。
2. **日志中心历史查询完全不可用**——前端请求 `entries?streamId=...&windowMinutes=60`，后端 schema 拒绝 `windowMinutes` 参数，页面顶部常驻英文技术错误条 `property windowMinutes should not exist`，条目查询/搜索/级别/时间筛选全部失效，仅剩 SSE 实时跟踪可用。
3. **删除当前活跃团队导致团队上下文静默失效**——多页面永久加载中且零提示，须用户自行重新切换团队才恢复。
4. **资源管控页「同步中…」按钮永久卡死**——进入页面即处于禁用同步状态，25+ 分钟未恢复，无超时、无失败态、无取消入口。
5. **创建向导「生成项目」点击后无任何反馈**——无 toast、无错误提示、无跳转，项目未创建成功（列表验证），用户无法感知失败原因。

## 3. 分域详评

### 3.1 落地页 `/`（公开）

**体验记录**：Hero（DEVPILOT  eyebrow + 主标题「一站式交付你的全栈项目」+ 副标题 + 双 CTA）+ 「核心功能」6 张静态卡片。视觉干净、信息层级清晰。

**问题**：
- [P2] 已登录用户仍看到「免费开始」CTA（SaaS 营销话术），与已登录态矛盾；自托管/内部平台的「免费」定位也值得商榷。
- [P2] 6 张功能卡片为纯静态 div，不可点击——用户无法从功能卡跳到对应模块（对比：Vercel/Render 落地页功能卡均有深链）。
- [P2] 无产品截图、无演示、无 footer 信息，对首次访问者缺少"平台长什么样"的预期建立。

**更好的预期**：已登录时 Hero CTA 变为「进入控制台」单一主按钮；功能卡可点击深链到对应模块；补充产品截图或交互预览。

---

### 3.2 认证 `/login`、`/register`

**体验记录**：已登录态访问两页均 302 → `/teams`。表单校验文案齐全（密码一致性、最少 6 位、强度提示、登录失败）。

**问题**：
- [P1] **「忘记密码?」是死链接**（`href="#"`，无 handler，代码内 TODO 自承占位）——展示为可点击链接等于承诺了不存在的功能。
- [P2] 登录后落地 `/teams` 而非仪表盘/我的项目，不符合"回到工作上下文"的预期。

**更好的预期**：死链下线或标注「暂不支持，请联系管理员重置」（参照 Railway Limited Access 的坦白式文案）；登录后落地 `/dashboard`。

---

### 3.3 仪表盘 `/dashboard`

**体验记录**：四层结构（待处理事项横幅 → 4 指标卡 → 最近部署/我的资源申请双栏 → 快捷操作）。DOM 链接审计发现：

- 「最近部署」6 行全部跳项目详情页（非该次部署的详情/日志），且 6 行内容完全相同（Picshare·开发·同一时间戳·blocked），无 commit、无分支、无耗时、无阻塞原因——**无法区分也无法行动**。
- 「查看全部」（最近部署）跳 `/applications` 而非部署历史列表，违反标签预期。
- 「添加凭证」快捷卡跳 `/resources`（资源连接库），与「密钥中心 `/keys`」语义重叠，用户会困惑凭证到底在哪管。
- 指标卡不可点击（项目总数 1 却不能跳项目列表）。
- 「暂无待处理事项，一切正常」横幅与下方一排 blocked 徽章同框，感知矛盾（虽然 blocked 部署刚好超出 24h 统计窗口，但用户不会这么算账）。
- 状态徽章英文直出（blocked/completed）。

**问题**：
- [P1] 最近部署列表信息密度过低且不可行动：无状态原因、无耗时、无 commit、跳转目标非部署详情。
- [P1] 「待处理」与「最近部署 blocked」视觉矛盾，异常检测窗口规则未对用户解释。
- [P2] 指标卡不可点击；「查看全部」目标错误；快捷操作语义重叠；英文徽章。

**更好的预期**（参照阿里云云效 AppStack 与 Vercel）：部署行应含 状态徽章+环境+commit 短哈希+触发者+耗时+相对时间，点击进该次 run 的详情抽屉（日志+操作）；指标卡可点击下钻；「待处理」区对 blocked>24h 的部署给出"已超出待办窗口"的次级提示或允许手动解除。

---

### 3.4 项目列表 `/projects`

**体验记录**：卡片网格，单卡含名称、「已有项目」来源徽章、「完整纳管」标签、创建日期、「有 Git 仓库」。

**问题**：
- [P2] 卡片信息稀疏：无技术栈、无描述、无最新部署状态/健康度、无快捷操作（部署/设置）——列表页无法回答"哪个项目现在状态如何"。
- [P2] 无搜索/筛选/排序（1 个项目时无感，规模上来即失效）。
- [P2] 无空状态演示（未验证 0 项目态，但代码显示有 CTA；建议空状态即主操作，参照 Netlify Drop）。

**更好的预期**（参照 Vercel 项目卡与 Railway Canvas）：卡片增加 框架图标+最新部署状态点+最近部署时间+环境摘要；顶部搜索框与来源/状态筛选；卡片右键或三点菜单提供 部署/设置/归档。

### 3.5 项目创建向导 `/projects/new`（5 步，全程实操）

**体验记录（评估前半段，页面健康时）**：
1. **基础信息**：项目名称（npm 规范提示）、组织名称（scope 示例 `@my-org/backend`）、描述、包管理器 radio——引导文案到位。
2. **子项目**：后端服务/管理后台/移动端小程序三卡，各带技术栈描述，至少选一个。
3. **功能选择**：按 基础设施/存储/通信/认证授权 分组，每项带「需要 redis / qiniu-kodo / sms-aliyun」依赖徽章——**依赖可视化是亮点**。
4. **资源配置**：数据库引擎三选一 + 每类资源的五种来源（跳过/手动填写/已有凭证/资源实例/资源池分配）——资源来源抽象设计良好。
5. **预览确认**：基础信息、子项目、引擎、业务功能、**将安装的依赖包（6 个 @svton 包逐项列出）**、**项目结构树预览**——预览信息密度是全场最佳之一。

**问题**：
- [P0] **「生成项目」点击后零反馈**：无 loading 态变化（截图前后字节级一致）、无 toast、无跳转、项目未创建。用户完全无法判断是点了没反应、在生成中、还是失败了。（当时正值全站取数降级窗口，但即便后端失败，前端也不该静默。）
- [P1] **向导草稿不跨刷新保留**：中途刷新/导航离开后，第 1 步已填内容清空（Zustand 草稿仅存活于内存）。五步长表单一朝丢失，挫败感极强。
- [P1] 第 3 步选了「缓存」（需要 redis），第 4 步**却不出现 Redis 资源配置行**（只有 MySQL/PostgreSQL 两类），预览页也不提示"所选功能依赖 redis 但未配置"——依赖校验在向导内断链。
- [P2] 「前端工具库」出现在预览页（"未选择前端库"）但**向导全程没有对应选择步骤**（后端 `registry/frontend-libraries` 接口无 UI 接线）。
- [P2] 第 4 步「数据库引擎」卡片选择与下方「资源配置」下拉是两个并列概念，用户不易理解二者关系（引擎决定模板，资源决定连接）。
- [P2] 「下一步」按钮为浅蓝色，视觉上像禁用态（与 /domain 生成按钮同一问题，全站性 affordance 误判）。

**更好的预期**（参照 Vercel 创建流）：① 生成按钮点击后进入"创建中"全屏态，展示实时生成日志/进度，成功失败皆有终态与重试（最佳实践：用实时反馈代替进度条）；② 草稿持久化 localStorage 并在重进时提示「继续上次配置」（配置预设功能其实已有此雏形，可复用）；③ 功能依赖（redis）自动在资源步浮现对应行并在预览页做缺失告警；④ 前端工具库补上选择步骤或从预览移除。

### 3.6 接入已有项目 `/projects/import`

**体验记录**：锚点导航长表单，「接入方式」三卡（已有代码项目/仅构建部署/外部管控项目）定义清晰、边界分明，是本页最大亮点。基础信息、仓库与技术栈、构建部署、环境分区条件渲染。

**问题**：
- [P2] 语言/框架为自由文本而非选择器（"Next.js / NestJS / Spring Boot"占位提示），录入不规范会直接影响后续展示与筛选。
- [P2] 长表单无侧边进度指示/必填总览，提交前无法预知缺什么。
- [P2] 无仓库连通性预检（填了 Git 地址不能先验证可达与凭证有效性，对比 Render 创建时的仓库扫描）。

**更好的预期**：语言/框架改 select+自定义；右侧粘性锚点导航带完成态勾选；仓库地址失焦即预检。

### 3.7 项目详情 `/projects/[id]`（6 个 tab 全巡检）

**概览 tab**：头部「异常」徽章 + 最近部署 Hero（已阻塞 + 查看错误）+ 关联应用 + 4 环境面板。
- [P1] **「已阻塞」状态的「查看错误」展开后只有一条良性提示「未配置默认分支，将使用 main」**——红色错误样式与内容严重不匹配，且完全没有解释"为什么阻塞、怎么解除"（实际是等待审批）。用户在最需要指引的地方得到的是误导。
- [P2] 「异常」徽章无 hover/点击解释，用户不知道异常从哪来。
- [P2] 「分支: -」空值直出。

**部署 tab**：
- [P1] 16 条部署运行**全部长得一样**（来源:手动 分支:- 开发 System Administrator），无时间、无状态、无耗时、无 commit——无法区分任何两次部署。
- [P1] 展开行只有「部署变量」（脱敏值），**无日志、无步骤、无结果**；retry/failure-rollback/smoke-check 三个后端端点完全未接线，发起部署/回滚只能绕道 `/applications`——**项目详情页是部署信息的洼地**。
- [P2] 「查看全部（16）」入口位置隐蔽；无分页/筛选。

**环境 tab + 抽屉**：
- 抽屉信息丰富（绑定服务器、资源计数 chips、普通变量编辑、资源实例注入、密钥深链、配置画像黄色预警、最近部署）——**配置画像预警是亮点**（"服务多 Picshare App/admin"提示部署命令归属歧义）。
- [P1] **资源 tab 与抽屉状态矛盾**：资源 tab 的「部署注入资源」复选框未勾选（res_picshare/db_picshare），而环境抽屉的「资源实例注入」却显示两者"按模板注入"——同一份绑定状态两个页面两种说法。
- [P2] 测试/预发/生产三个环境默认「已启用」但全空（0 部署），没有"尚未配置"的引导态。
- [P2] 普通变量无批量粘贴 .env 能力（Railway/Render 标配）。

**Webhook tab**：
- [P1] 只读空态「暂无 Webhook 通知」（文案错误：这是 webhook 配置不是"通知"），**后端 create/update/rotate-secret/deliveries 四个端点全部无 UI**——用户连一个 webhook 都建不了，Git 推送触发部署的链路在前端是断的。
- [P2] 空态无 CTA、无文档链接。

**资源 tab**：
- 关联资源到环境的说明文案（envTemplate 注入机制）写得专业清楚。
- [P2] 「已选 1 项」计数与勾选联动正常，但保存后无成功反馈验证（评估窗口内未提交）。

**设置 tab**：
- [P1] 仅名称/描述可编辑：**无归档/删除项目入口、无 Git 仓库改绑、无默认分支配置**（而那正是"阻塞原因"提示的修复点！设置页解决不了设置问题）。
- [P2] Git 仓库展示为纯文本不可点击。

**更好的预期**（参照 Vercel 项目详情与 Railway 服务页）：部署 tab 应成为"部署时间线"（状态+commit+耗时+可展开日志+重试/回滚/Promote 操作）；阻塞状态给出审批深链「前往操作审批 →」；设置页补齐危险区（归档/删除）与默认分支配置；Webhook tab 补齐 CRUD 与投递记录。

### 3.8 应用与部署 `/applications`（核心链路，全程实操）

**体验记录**：5 指标卡 + 应用卡（Picshare App：admin/backend 两服务）。服务行：active 徽章、Docker Compose、环境、SLO 概览行、最近操作。操作：**部署 / 状态 / 更多操作（日志/重启/回滚 + 申请 Live 版重启/回滚）**。

**部署弹窗（全场最佳交互）**：三步内联向导（选环境→预览计划→选择操作）；dry-run 预览展示 执行步骤（拉取代码→构建→写入环境配置→部署→健康检查→清理环境配置）+ 脱敏注入变量 + toast「预览计划已生成」+ 「申请正式部署（需审批）」按钮。**dry-run 前置 + 审批门控的设计优于多数同类平台。**

**问题**：
- [P1] 点击「日志」菜单项**不是打开日志查看器**，而是静默执行一次 logs 操作并新增一条运行记录（40→42 次运行实时递增），用户拿不到日志内容——操作语义与结果交付不符（与资源管控"查看详情看不到详情"同一病症）。
- [P1] SLO 概览行文本截断「1440m · 窗口内暂无真实部署、服务操作或服务…」，「无数据」徽章与截断文案并存，信息既不完整也不美观。
- [P2] 最近操作行全部雷同（状态/完成/试运行 同秒三条），无法区分；英文 `active` 徽章；队列模式开关×2 无说明。
- [P2] 「状态」按钮触发的是一次 dry-run 状态探测（产生运行记录），而非即时状态展示——用户预期与实现有偏差。

**更好的预期**（参照 Render/Railway）：「日志」应打开内嵌日志面板或深链日志中心对应流（`?streamId=`）；「状态」应展示缓存的最近探测结果+「重新探测」按钮；SLO 行截断改 tooltip 完整文案；操作历史区分动作类型图标。

## 4. 跨域系统性问题（按主题归纳）

### 4.1 稳定性与兜底（最严重）
- 页面取数挂起 = 永久 spinner，**全站没有一个页面有超时、错误态、重试按钮**。
- 后台任务（Docker 同步）卡死疑似可拖垮全站服务端取数——任务隔离与熔断缺失。
- 前端对后端失败普遍静默（生成项目零反馈、评估按钮零反馈）。

### 4.2 "只能建、不能管"的写后管理缺失
- 告警规则、日志流：API 层就没有 DELETE。
- 告警规则 PUT 可用但 UI 不暴露；服务器连接信息不可编辑；项目无法归档/删除；Webhook 无法创建；环境无法创建/归档（后端端点存在）。
- **13 组后端有能力、前端无入口**（部署 retry/smoke-check、webhook CRUD、资源池分配链路、环境管理大半、密钥编辑/导出、Git 建仓/推文件、admin 用户管理、资源管控读端 4 个、registry resolve 等）——功能版图与用户可达能力严重不符。

### 4.3 反馈一致性
- toast 时有时无（创建规则有，建流/预设/团队/策略无）。
- 弹窗一半有「取消」一半没有（备份、策略、访问策略无）。
- 安全等级倒挂：删除有确认，而停用策略/队列开关/删除站点等中高危操作反而无确认。
- 表单校验全靠 HTML5 原生气泡，无产品化行内报错。

### 4.4 语言与文案
- 中英文混杂贯穿全域：状态徽章（active/blocked/running/idle）、分类枚举（site_sync/account/cache）、技术名词（ServerExecutionLease、dry-run）、占位符、种子数据英文描述。
- i18n 占位符直出「审批：{value}已批准」。
- 侧边栏与页面标题三处不一致；「暂无 Webhook 通知」等文案错误；错误信息以英文技术原文直出（`property windowMinutes should not exist`）。

### 4.5 状态可信度
- 同步「完成」但日志显示 systemctl 失败；「已阻塞」配良性提示；资源勾选态两页矛盾；检测模拟数据自相矛盾——**多处状态展示与事实不符，比没有状态更伤害信任**。

## 6. 改进路线图建议

**第一优先级（P0，本周）**：
1. 全站取数兜底：统一 SWR/RSC 超时（如 15s）→ 错误态组件（含重试按钮），消灭一切永久 spinner。
2. 修复日志中心 `windowMinutes` 契约 bug；错误信息用户化（错误码+建议操作，技术细节折叠）。

4. 修复资源管控同步卡死（超时+取消+失败态）；排查其阻塞全站取数的链路（连接池/锁）。
5. 创建向导生成按钮：loading 态+成功/失败终态 toast+失败重试。

**第二优先级（P1，两周内）**：
6. 部署 tab 重建为时间线（状态/commit/耗时/日志展开/重试回滚），接线已有后端端点。
7. 阻塞/异常状态给出原因与解除路径（审批深链）；「完成」判定以实际执行结果为准。
8. 修复三处状态矛盾（站点卡片元信息、资源勾选态、`{value}` i18n）。
9. 废弃页收口：/proxy-configs 新增入口下线、服务器详情按钮改跳 /sites 并修预填；/domain /cdn 加入侧边栏「工具」分区或彻底移除。
10. 补齐写后管理：告警规则/日志流删除、服务器连接信息编辑、项目归档删除、Webhook CRUD。

**第三优先级（P2，月度）**：
13. 中英文统一（状态徽章映射表）；侧边栏与标题命名对齐。
